# 飞书私聊诊断

飞书企业自建应用通过官方 Java SDK 的 WebSocket 长连接接入 SupportOps。用户在机器人私聊中完成账号绑定后，发送文字问题即可创建诊断；机器人返回受理提示及最终结果。每条问题独立创建会话，完整问答、证据、事件和用量保留在工作台。

当前支持一个应用、一个企业和单实例工作台。只处理用户的文字私聊，忽略群聊、机器人消息、附件及超过三十分钟的旧消息。当前示例环境同一时间只受理一个诊断，忙碌时明确拒绝本次问题，用户可稍后重新发送。机器人接入不改变四个只读 MCP 工具及固定示例环境的范围。

## 创建与配置应用

1. 在[飞书开放平台](https://open.feishu.cn/app)创建企业自建应用，启用机器人能力，将应用可用范围限制到试用人员。
2. 申请读取用户发给机器人的单聊消息、以应用身份发送消息的权限。事件订阅选择 **接收消息 v2.0**（`im.message.receive_v1`），使用长连接方式。无需填写公网回调地址，也不需要开放工作台的入站端口。
3. 从开发者后台取得 App ID、App Secret 和所属企业的 tenant key。企业编号用于服务端校验消息所属企业，不能填写用户 open_id 或群编号。
4. 将下列配置追加到本机 `.local/model.env`，已有同名项应修改原条目。真实密钥仅填写在本机，不提交 Git。配置由启动时读取，修改后需要在无活动诊断时重启服务。

```dotenv
SUPPORTOPS_FEISHU_ENABLED=true
SUPPORTOPS_FEISHU_APP_ID=你的应用编号
SUPPORTOPS_FEISHU_APP_SECRET=你的应用密钥
SUPPORTOPS_FEISHU_TENANT_KEY=你的企业编号
```

`SUPPORTOPS_FEISHU_ENABLED` 默认 `false`；停用时不创建长连接、不发送消息，后台仍可查询记录和撤销绑定。对话模型、向量服务及检索策略沿用工作台统一配置；对话模型未配置时返回明确提示。向量服务已配置且存在适用索引时使用混合检索，否则使用关键词检索；进入向量调用后发生错误仍明确报告，不静默降级。

飞书不提供独立的检索方式开关。网页聊天框的“仅关键词检索”是本次网页诊断的临时选择，不影响飞书。旧配置中的 `SUPPORTOPS_FEISHU_LEXICAL_ONLY` 已停止生效，启动脚本兼容忽略该条目及继承环境中的同名变量，可从旧文件删除。

仓库的隔离评测脚本强制停用飞书渠道，并移除继承的飞书环境配置，避免测试实例接收真实私聊。

5. 使用 `node scripts/start.mjs` 启动已打包应用，在后台 **飞书机器人** 页面查看状态；飞书后台需要在线长连接才能完成部分订阅配置时，可先启动，再保存订阅并发布应用。仅“配置完整”不代表鉴权成功，“已连接飞书”也不代表应用权限和可用范围已经通过真实收发验证。
6. 按飞书后台要求保存权限、事件配置并发布版本，确认试用账号能够与机器人私聊。

生产代码固定使用飞书官方端点，不支持自定义平台地址。SDK 原始日志默认关闭，避免带签名的连接地址或平台内容进入日志。应用提供脱敏连接状态及消息处理状态。

## 绑定与使用

管理员先在 **用户管理** 创建工作台账号，再进入 **飞书机器人**，选择该同事的账号并生成绑定命令。将命令通过可信渠道交给该同事，由其在机器人私聊中发送。

绑定码具有 192 位随机熵，十分钟有效，消费后失效；数据库只保存 SHA-256 摘要，不保存命令原文。同一个应用和企业内，一个飞书 open_id 只能对应一个工作台账号。管理员可撤销绑定；撤销保留诊断和消息记录，阻止后续受理及尚未开始的结果投递，不撤回已经发送的消息或自动取消已受理任务。

绑定成功后直接发送 1–6000 个字符的问题。机器人先回复任务编号，诊断进入终态后再回复结果。回答超过 3500 个 Unicode 字符时明确标注节选，完整结果仍在本机工作台。页面继续仅支持本机访问，因此回复不附带手机无法打开的本机报告链接。

诊断回答和原始工具证据保留来源时间；工作台显示回答、生成新的飞书回复时，才将正文中带明确时区的 ISO 时间显示为 `yyyy-MM-dd HH:mm:ss（北京时间）`，精确到秒。日志代码块中的时间应保留原样；工作台也会格式化已有回答的展示，不改写历史记录或已经发出的飞书消息。无时区或无效时间保持原样，不推测所属时区。

群聊触发、多轮上下文、附件解析、交互卡片及跨主机网页登录不在当前接入范围。

## 持久化与恢复

- **收件去重**：应用编号、企业编号和平台消息编号组成唯一键。收件或绑定操作在短事务中提交后，SDK 才确认事件；持久化失败交由平台重投。
- **诊断幂等**：先保存收件 UUID，再用同一 UUID 受理诊断。任务保存后关联更新失败、事件重投或进程重启，都读取同一任务；不重新调用模型。身份来自绑定记录，后台线程不借用管理员 Cookie，也不依赖空的 HTTP 身份上下文。
- **状态恢复**：沿用原诊断的重启中断语义。重启后读取已完成或已中断任务，并创建相应结果回复。保存回复和更新收件状态处于同一事务。
- **冻结回复**：回复的接收身份、文本和发送 UUID 保持不变。网络请求在事务外执行，失败只重试投递，不重跑诊断。受理提示先结束投递流程，结果才发送。
- **有限补发**：最多五次发送尝试，逐步延长间隔。飞书发送接口对相同 UUID 提供一小时去重；SupportOps 只在首次尝试后的五十分钟内自动重试。超过窗口标记 `UNKNOWN`，停止盲目重发。`FAILED` 表示尝试耗尽、送达尚未确认，不证明飞书一定没有收到；需核查实际私聊与平台记录。
- **撤销检查**：准入及发送前重新查询绑定，旧应用、旧企业或已撤销身份不能取得诊断结果。已经开始的网络发送无法追溯撤销。

此恢复机制不提供多实例诊断调度；不要使用多个 SupportOps 进程同时连接同一业务数据库。

## 管理接口

以下接口遵守现有 Cookie、请求头及同源校验，均仅管理员可用。生成的中文 OpenAPI 可在工作台 Swagger 页面查看。

| 方法与路径 | 用途 |
| --- | --- |
| `GET /api/feishu/status` | 本地配置完整性与连接状态；不返回密钥 |
| `POST /api/feishu/bindings` | 为已有 `userId` 签发一次性绑定命令；仅本次响应返回明文 |
| `GET /api/feishu/bindings` | 当前应用和企业最近一百条绑定；不返回明文码或摘要 |
| `POST /api/feishu/bindings/{id}/delete` | 撤销绑定，重复操作幂等 |
| `GET /api/feishu/messages` | 最近一百条收件与投递状态；不返回问题及回复正文 |

`FINISHED` 表示回复已生成；是否送达须检查每条回复的 `SENT`、`PENDING`、`FAILED`、`UNKNOWN` 或 `BLOCKED` 状态。

## 数据迁移与验证边界

[V5](../src/main/resources/db/migration/V5__feishu_private_diagnosis.sql) 增加 `feishu_bindings`、`feishu_inbox`、`feishu_outbox` 三张表，不改写已有账号、诊断、文档和 V4 归档数据。已有库升级前备份并核对连接目标，由 Flyway 应用增量；不通过清空数据库升级。飞书停用也会正常应用结构迁移。

`FeishuPersistenceTest` 使用独立真实 MySQL 验证绑定消费、过期、并发去重、事务回滚、归属校验、忙碌拒绝、撤销、重启中断及冻结回复重试。`FeishuProtocolTest` 使用官方 SDK 和本地 HTTP 端点验证令牌请求、发送载荷和接收事件解析。仅靠这些用例不能证明真实飞书的应用鉴权、权限、长连接重连或消息送达；真实平台结果另列如下。

本地数据库、接口、SDK 协议及管理页面的检查结果见[验证记录](validation.md#2026-09-22-飞书私聊接入验证)。真实联调应使用指定测试企业、测试应用和明确允许接收回复的账号，验证：私聊绑定、未绑定拒绝、真实诊断、忙碌反馈、结果送达、断线恢复及撤销后的拒绝。真实联调状态应与本地协议验证分别记录。

2026-09-23 使用仅对指定测试账号开放的应用完成真实私聊联调：应用鉴权与长连接、未绑定提示、一次性绑定、真实模型诊断的受理和结果送达、撤销后的拒绝均通过；隔离进程冷重启后连接恢复，已送达回复没有重复发送。忙碌反馈、网络故障中的自动重连与不确定送达补发尚无真实平台故障注入记录，详见[当日验证记录](validation.md#2026-09-23-诊断时间展示与原文留存)。
