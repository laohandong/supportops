# SupportOps 产品定义

## 用户与任务

软件实施与技术支持人员，在客户报障之后、研发深入处理之前，收集环境事实、核查产品资料并形成可审阅的诊断建议。

## 产品范围

当前版本围绕一个 Java 示例应用和单 Agent 提供问题提交、四个只读 MCP 查询、关键词 / 向量融合检索、可选本地模型重排序、Excel 只读数据查询、文件式 Skills、人工确认的项目约束与诊断记录。环境变更由人员执行。文档支持 Markdown、文字型 PDF 与 Excel，保留原件、修订及异步处理历史；MySQL 保存业务事实，MinIO 保存原件，Elasticsearch 保存检索索引。

菜单按使用场景分为客户工作区与后台管理：客户工作区包含诊断工作台、新建会话和最近诊断；后台管理包含知识文档、项目约束、示例环境、用量分析、模型配置与用户管理。管理员可以查看全部菜单，普通用户只能访问客户工作区与本人的对话；权限由服务端校验。

诊断通过 SSE 展示公开回答与执行证据，支持分类查看、历史回看、JSON 导出和整个会话的逻辑归档。归档隐藏侧栏记录并禁止追加诊断，保留问答、证据和用量。管理员用量分析支持时间趋势、会话排行及逐轮回看，不把执行完成或 Token 消耗当作回答质量评分。

## 操作环境

本地工作台，提供管理员与普通用户账号。示例应用与下游均为自建，业务数据为合成数据。文档上传及关键词检索可独立使用；模型诊断和向量索引需要配置对应服务。侧边栏提供独立的对话与向量配置，保存后无需重启；向量服务可以关闭。

## 产品原则

- 结论关联可核查的工具或文档来源。
- 区分当前事实、历史资料与待验证假设。
- 任务失败、资料缺失和服务未配置均展示真实状态。
- 首版范围与后续路线图分别描述。
