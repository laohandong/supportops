## EC-A01：中断恢复拒绝尚未入库的已完成结果

优先级：**P1，阻塞最终验收**。

触发条件：Node 已写出合法的样本 JSON 与 `CASE_FINISHED` 事件，管理进程在该事件入库前中断或丢失租约。

代码链路：

1. `EvaluationExecutionServiceImpl.claimRecovery()` 第 114–124 行提升 guard/attempt 的 fencing token，并立即把实验设为 `INTERRUPTED`。
2. `EvaluationRunnerImpl.recover()` 调用 `finalizeAttempt()`，后者第 230 行仍通过普通 `ingest()` 消费原事件。
3. 原事件持有旧 token，`EvaluationResultServiceImpl.ingest()` 第 106–113 行拒绝。即使只替换事件 token，终态保护仍会拒绝。
4. 该异常在原错误已为 `EVALUATION_OWNER_LOST` 时没有单独记录；终结继续将未完成数据库样本改为 `SKIPPED`。随后常规页面与导出读不到已经完成的回答与证据。

独立探针实测：

```json
{
  "completedResultStillExists": true,
  "oldToken": 1,
  "recoveryToken": 2,
  "rejected": "EVALUATION_FENCING_CONFLICT",
  "persistedSample": {
    "status": "SKIPPED",
    "answer": null,
    "error_code": "EVALUATION_OWNER_LOST"
  }
}
```

已有测试证明了“已经入库的样本不会丢失”，没有覆盖“完成结果已经落盘、完成事件尚未入库”的窗口。

修复要求：

- 在旧进程身份及退出状态得到确认后，为当前恢复持有者提供受控的历史结果补录路径，区分恢复权限 token 和原始事件执行 token。
- 保留事件原文、摘要、连续序号、文件长度与摘要校验、资源归属、事务和去重。不能简单关闭普通导入的 token/终态校验，不能改写原事件伪装新 owner。
- 实验总体仍保持 `INTERRUPTED`，不重新调用模型；允许合法已完成样本保存其原完成状态、回答、证据和用量。
- 补录失败应记录可诊断且可重试的状态，避免在证据尚未妥善保存时不可恢复地结束补录流程。

复验条件：至少覆盖完成文件和事件已落盘但尚未入库、部分事件已入库、重复恢复、截断尾事件、旧 owner 迟到写入、数据库导入失败回滚。合法完成样本可从数据库及导出读取，实验不变为成功，不增加模型 POST；旧 owner 仍无法写入。
