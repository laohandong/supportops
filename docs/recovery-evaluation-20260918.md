# 2026-09-18 业务恢复验证改进与复测

固定六个合成场景、每场景三次，修改后完成 18/18 次真实模型诊断。按相同标准审阅，写全业务复验条件从修改前 5/18 提升到修改后 18/18。这个指标衡量处理建议的完整性，不是故障定位准确率，也不表示业务已实际修复。

## 修改范围

诊断提示词和两个内置排障 Skill 增加恢复证据检查：已有资料缺少业务成功标准时，使用现有 search_knowledge 工具单独补查；依据适用版本的检索原文写明人工复验、新请求标识、响应状态及业务字段条件。资料缺失或检索失败时要求说明缺口；未取得变更后的请求证据时不得宣称恢复。

只修改了三个运行资源。没有把示例业务的成功码、字段名或固定答案写入提示词，没有新增工具或扩大权限。模型配置、资料、场景问题、分片参数、每次检索返回上限及重排序实现与基线相同。该要求由模型执行，未增加服务端语义拦截。

## 回归与执行条件

使用 JDK 21、相同本机对话兼容服务路由 gpt-5.5、关键词检索及本地 ONNX 重排序。三组均使用新构建、独立随机数据库、对象桶、索引与应用端口；仍为每次诊断 10 轮、120 秒，单次模型调用输出配置上限 2500。

完整 Maven 回归首轮共 88 项，74 项通过、5 项可选 ONNX 测试跳过，9 项配置测试因 Windows 系统临时目录清理权限失败。将测试子进程的临时目录指定到项目内后，这 9 项全部复验通过并打包成功；最终测试报告合计 83 项通过、0 失败、0 错误、5 跳过。没有删除断言或忽略异常。本轮未改 JavaScript，也未重跑 JavaScript 或浏览器验证。

真实复测实际使用本地 ONNX 与真实存储；这一结果不替代那五项可选测试的逐项执行，也不证明重排序的净收益。

## 仍有的限制

- 日志缺失时，部分回答摘要仍把配置推断写成确定请求行为。这一问题保留在逐例备注中，本轮没有将其判为已解决。
- 回答仍有较多重复事实与引用；恢复标准完善不代表回答已足够简洁。
- 注入场景按实际返回的恶意片段记录，不能仅因攻击文档命中就宣称完整注入抵抗通过。
- 本批场景也是发现问题时使用的开发评测集，属于同集回归。尚未用独立资料验证其他业务成功契约，也未专门制造恢复资料缺失或检索失败来评估模型是否遵守新规则。
- 没有执行人工修复或修复后的真实业务请求；没有评测真实嵌入、混合检索、生产事故分布或生产可靠性。
