# 诊断处理结果与评测案例沉淀 V1 开发任务及验收

日期：2026-10-02。状态：待开发。本文与[功能技术设计](diagnosis-outcome-cases-design.md)共同构成实施范围。任务表及测试编号是计划，不表示已经实现或通过。

## 执行方式

本轮在一个开发任务内贯通结果回填、案例发布和评测执行，按下列依赖连续推进。任务编号不是反复请求确认的停点。先完成必要实现、修复和隔离验证，再交付独立验收；后续人工质量基线另立开发包。

1. 阅读根 [AGENTS.md](../../AGENTS.md)、本设计与清单；检查当前 Git 状态和相关源码。已有大量未提交功能是工作基础，保留其内容，不清理、还原或覆盖。
2. 使用 Java 21、仓库 Maven Wrapper、Node 22。共享 `target/` 的 Maven 构建串行执行；先核实正在使用的程序包与运行目标。
3. 使用独立数据库、对象前缀、索引、回环端口、运行目录及明确归属的测试资源。现有工作台、真实服务商及飞书不作为默认测试目标。
4. 本轮允许完成设计范围内的代码、增量迁移、页面、测试、修复和文档；不提交、推送、发布或替换日常工作台。资源回收仅限本轮创建且核实归属的资源。
5. 类名、局部拆分和普通交互细节由开发者决定。若当前源码变化使权限、不可变版本、原请求恢复或受控执行边界无法成立，说明具体冲突再处理；不把常规实现选择变成审批问题。
6. 功能测试优先真实存储加本地协议夹具。真实模型和嵌入调用待明确运行范围后另验，不以协议夹具报告模型效果。

## 任务顺序

```text
OC-01 契约与接入核对
  → OC-02 持久化与升级
  → OC-03 处理结果服务和权限
  → OC-04 案例草稿与不可变发布
  → OC-05 数据集和执行器兼容
  → OC-06 页面与请求恢复
  → OC-07 隔离功能和恢复验收
  → OC-08 文档及证据交付
```

前端可在接口冻结后推进，最终仍按整条流程验收；不要只交付后端或只做能点击的表单。开发中可先贯通一个案例，然后覆盖下列全部必测项。

| 任务 | 相对复杂度 | 交付重点 |
| --- | --- | --- |
| OC-01 | 小 | 身份、状态、数据集和执行协议的兼容边界 |
| OC-02 | 中 | 新迁移、约束、版本与幂等事务 |
| OC-03 | 中 | 结果回填、证据投影、真实权限和历史 |
| OC-04 | 大 | 人工草稿、脱敏、来源更新、冻结发布 |
| OC-05 | 大 | 非内置编号实际执行、旧包兼容与报告 |
| OC-06 | 中 | 原工作台中的完整交互和未知请求恢复 |
| OC-07 | 大 | 真实数据库、浏览器、协议夹具及备份恢复 |
| OC-08 | 小 | 用户文档、接口定义、逐项证据和复验入口 |

相对复杂度用于安排顺序，不作为工期承诺。开发者可以持续跨上下文完成同一任务，交付记录应如实标明完成与阻塞，不把计划改写成验收结果。

## OC-01 契约与复用核对

主要入口：

- `src/main/java/io/supportops/agent/service/RunService.java`、`agent/controller/RunController.java`。
- `src/main/java/io/supportops/api/UserAccessFilter.java`。
- `src/main/java/io/supportops/remediation/service/RemediationService.java`、`remediation/vo/RemediationViews.java`。
- `src/main/java/io/supportops/evaluation/dto/RunnerProtocol.java`、`evaluation/vo/EvaluationViews.java`。
- `evaluation/contracts.mjs`、`evaluation/run.mjs`、`scripts/center-runner.mjs`。

工作内容：

1. 固定四类处理结果、三类证据、案例条目/草稿/发布版本、用途和复现能力的定义。
2. 确认来源事件、关联修复证据和来源结果版本通过服务读取；补充只读投影和发布时来源锁定接口。
3. 区分数据集格式、执行清单格式和公共事件格式，列出旧格式的读取、排队、清理、恢复入口。
4. 定义 DTO/VO、字段上限、错误码、服务端身份、规范化摘要和原请求回执。明确 JSON 未知敏感字段的拒绝规则。
5. 核查当前最高迁移及运行实例；记录源码基线，给后续独立验收保留交付对象身份。

完成条件：契约能在设计范围内直接实现；不能把“案例 ID 不再固定”解释为允许任意场景或执行参数。

## OC-02 数据层与增量升级

主要入口：`src/main/resources/db/migration/`、新 `outcome/entity` 和 `outcome/mapper`、`evaluation/entity` 和 `evaluation/mapper`、相应 Mapper XML。

工作内容：

1. 核实后新增 V11 或下一可用迁移号，实现设计中的七张表及 `evaluation_cases.library_revision_id` 可空外键。
2. 使用 MyBatis-Plus，保留 UUID、UTC 时间及字符集语义；固定结构使用类型化 JSON，不在 Service 中拼接 SQL。
3. 结果主记录、不可变修订、成功回执原子写入；草稿编辑/发布、审计和回执原子写入；数据集全部案例原子写入。
4. 实现来源唯一、修订唯一、请求键唯一、分页索引、旧版本条件更新及影响行数检查。
5. 新模块不得创建跨模块 Mapper 依赖；明确行锁顺序，覆盖并发创建、发布与来源更新。

完成条件：真实隔离 MySQL 上验证空库初始化、V10 升级、旧数据读取、约束、回滚和并发。旧八份迁移字节保持一致；使用独立 JDBC 查询核对最终状态和计数。

## OC-03 处理结果与权限

主要入口：新 `src/main/java/io/supportops/outcome/`、agent 只读来源接口、remediation 只读证据投影、`UserAccessFilter`。

工作内容：

1. 实现读取、保存、历史、原请求回执；无记录与未解决严格区分。
2. 所有者或 ADMIN 可为终态诊断回填；归档不阻止回填；服务端确定 actor，拒绝 owner/确认人伪造。
3. 三类证据校验来源和存在性；关联修复必须匹配 sourceRunId；读取证据不得触发 execute、reconcile 或发送业务验证请求。
4. 普通用户读取采用白名单摘要；管理员完整回执不得进入普通用户响应、历史或缓存。
5. `RESOLVED` 与 `PARTIALLY_RESOLVED` 需要处理后的验证；修复 UNKNOWN、诊断前故障或单独应用成功不能直接满足验证条件。
6. 实现固定请求恢复、版本冲突和历史修订；后续修订不更新来源事件、模型回答或用量。

完成条件：真实 HTTP 覆盖管理员、普通用户 A、普通用户 B，校验状态码与数据库不变性；并发编辑只有一个版本生效，重试不重复增加历史。

## OC-04 案例候选与不可变发布

主要入口：新 `EvaluationCaseLibraryService`、对应 Controller/DTO/VO/Mapper；outcome 来源快照接口。

工作内容：

1. 从处理结果创建候选；同一来源 run 复用条目；原始记录只引用、不整段复制；先提供可编辑草稿。
2. 实现名称、脱敏问题、用途、受控场景、差异说明及四组人工标准。
3. 可执行性检查由服务端白名单决定。无法映射时保存候选，返回明确阻断码；不提供伪造通过开关。
4. 自动敏感内容检查加人员确认；展示最终草稿摘要与材料版本，发布重新核对草稿、来源及角色。
5. 来源回填被修改后，草稿须显式刷新来源并重新确认；并发来源更新与发布不能越过版本检查。
6. 实现发布版本、下一版草稿、审计、归档与恢复；历史版本和已有数据集不被覆盖。
7. 人工标准和来源事实仅用于评测侧与管理员页面；不进入被测 Agent 上下文和知识库。

完成条件：能保存不足以复现的候选，也能发布一个经确认的可执行案例；新版本与原数据集的内容摘要独立保持稳定。

## OC-05 数据集与执行链路

主要入口：

- `src/main/java/io/supportops/evaluation/service/impl/EvaluationDatasetServiceImpl.java`、`EvaluationServiceImpl.java`、`EvaluationRunnerImpl.java`、`EvaluationAnalysisServiceImpl.java`。
- `src/main/java/io/supportops/evaluation/service/support/EvaluationSnapshotService.java`。
- `src/main/java/io/supportops/evaluation/dto/EvaluationRequests.java`、`RunnerProtocol.java`、`evaluation/vo/EvaluationViews.java`。
- `evaluation/contracts.mjs`、`evaluation/run.mjs`、`evaluation/report.mjs`、`scripts/center-runner.mjs`、`scripts/evaluate.mjs`。

工作内容：

1. 从已发布修订组成最多 30 例的不可变数据集；不混合用途、不同材料包或重复条目。数据集组成不启动任何模型或创建运行资源。
2. 保留每实验 6 例、3 策略、5 重复、90 样本上限和原有预算；新旧数据集在同一实验界面选择。
3. 支持新案例 ID 与场景分离；同一场景多个问题可独立记录、排序、重复执行及审阅。
4. 实现清单格式二的 Java/Node 兼容。旧格式一仍按原白名单读取；未开始的旧队列、已冻结旧包、恢复与清理路径均可处理。
5. 核对实际 JAR 资料、注入材料、分片参数与案例快照；不一致拒绝运行。冻结后编辑草稿或工作区文件不改变实验输入。
6. 逐例重置场景、清理注入材料；保留现有进度、事件顺序、取消、终态、未知提交停止、证据补录和资源归属检查。
7. 报告与比较增加案例发布身份、用途和复现差异。不同问题/标准/材料版本拒绝单变量效果归因；旧报告继续可读。

完成条件：至少两个新案例 ID 映射同一场景实际执行成功，并有一个其他场景证明不是单案例特例；原内置六场景来源检查保持通过。不能只修改校验器并声称运行链路已支持。

## OC-06 页面与原请求恢复

主要入口：`src/main/resources/static/app.js`、`index.html`、`evaluation.js`；新增独立 outcome/case-library JS/CSS；`src/test/js/` 与 `src/test/e2e/`。

工作内容：

1. 诊断详情提供回填、确认、历史和管理员案例入口；执行中与无记录有清楚提示。
2. 案例列表、编辑、来源更新提示、阻断原因、发布预览、版本历史、归档/恢复、组成数据集及跳转实验草稿形成完整流程。
3. 显示“人员陈述”“合成复现”和冻结版本，不将处理结果当作模型得分。
4. 发送前固定命令；刷新、超时、断网、登录失效和后到响应使用原请求恢复，不产生新 requestId；查询失败不能解锁新命令。
5. 响应与当前部署、账号、条目、版本和读取序列绑定；切换记录或账号后旧请求结果不能覆盖新页面。
6. 浏览器存储不可用时保留当前内存命令并说明恢复限制；重新打开页面不自动启动模型或提交写操作。
7. 保留原 SSE、评测轮询和修复恢复组件的行为；只增加必要接点，不做整体前端重构。

完成条件：真实浏览器完成正常链路及权限、冲突、刷新、响应丢失等异常链路；用界面以外的数据库和服务端事件核对重复次数。

## OC-07 必测矩阵

每个编号都须在开发报告中对应 PASS、FAIL 或 NOT_RUN 及证据。原始失败保留，修复后追加复验，不能用删除断言或略过检查使报告变绿。

### 结果与权限

| 编号 | 场景 | 必须证明 |
| --- | --- | --- |
| O01 | 四状态、无记录、不同诊断终态、归档后回填 | 字段要求正确；未填写不等于未解决；未终态拒绝且库不变 |
| O02 | ADMIN、普通 A、普通 B、未登录 | 401/403/404 边界；他人来源及事件不可枚举；所有 GET 无隐式写入 |
| O03 | 证据不存在、跨诊断、跨修复来源 | 拒绝伪造关联；普通用户响应不泄漏管理员回执 |
| O04 | 诊断前故障、修复 UNKNOWN、应用成功但验证失败 | 不能单独支持已解决；独立人员观察按人员陈述保存 |
| O05 | 同键并发、不同键同版本、同键改正文 | 一次提交和一次历史；版本或内容冲突明确；失败事务无半条记录 |
| O06 | 修订、重启、归档及重新读取 | 旧修订不变；actor 来自登录态；回答、事件、Token 不受回填影响 |

### 页面与恢复

| 编号 | 场景 | 必须证明 |

| U04 | 浏览器存储失败、页面重开、键盘、窄屏、空列表 | 可理解的状态与恢复限制；无自动写入、启动或无声丢失 |

以上 29 个验收编号是本轮最低矩阵，不以测试方法数量替代覆盖。O/C/U/R 可由集成测试和 E2E 联合证明，但必须保留实际断言和证据定位。

### 回归运行要求

- Java 因涉及持久化、权限和分层，使用 JDK 21 执行仓库 Maven Wrapper 完整 `verify`；新测试须访问真实隔离 MySQL。失败先区分代码与环境，修复后重验受影响部分。
- Node 执行 `node --test src/test/js/*.test.mjs`；新执行清单、固定命令和格式兼容必须有测试。继续保留已有评测与受控修复断言。
- 使用现有 Playwright 入口扩展 U01–U04，不以 DOM 片段单测替代真实页面交互。记录截图和步骤，但截图不能替代权限/持久化断言。
- 在 Windows 完成完整功能链路，并在 Linux 验证新执行协议、来源检查和取消/恢复受影响路径。可复用已有 Linux 交付环境，保留其明确归属；本地 Linux 结果不等于远程 CI 已运行。
- 使用完整冻结的最终 JAR 与执行包复验关键链路。若最终构建改变了相关类、脚本或静态资源，需重验对应行为，不能沿用旧包结论。
- 备份恢复继承现有容量和拒绝规则；新增表无需机械重跑与本轮无关的全部大索引故障矩阵，但新记录恢复、旧备份升级和被修改脚本的相关回归必须完成。
- 无真实 ONNX 文件时保留可选检查的未执行说明。本轮未改 ONNX 行为，不以下载权重或外部调用扩大范围。

## OC-08 文档与交付证据

新增面向用户的 `docs/diagnosis-outcomes.md`，说明处理结果含义、人员陈述、证据来源、权限、修订和案例转入流程。同步更新 `docs/evaluation-center.md`、`docs/api.md`、`docs/database.md`、`docs/users.md`、`docs/architecture.md`、`docs/reliability-delivery.md`、`docs/validation.md`、`docs/README.md` 及相关评测说明。README/ROADMAP 只描述实际完成能力，不提前宣称质量提升。

必须检查运行应用生成的 OpenAPI：所有新增 GET/POST、请求头、身份边界、DTO 引用、枚举、字段限制、版本和错误码均与实现一致。注解编译成功不等于接口定义验收通过。

开发验收记录放在 `docs/diagnosis-outcome-cases-acceptance-YYYYMMDD.md`，至少包括：

1. 最终 JAR、执行脚本、关键源码与迁移的摘要；记录交付前后 Git 状态，区分已有修改和本轮增量。
2. OC-01–OC-08 完成情况，以及 O01–O06、C01–C14、U01–U04、R01–R05 的逐项结果和证据相对路径。
3. Java、JS、浏览器、Windows/Linux、来源检查、协议夹具和恢复的执行范围；失败历史、跳过原因和修复复验分别记录。
4. 受限配置、报告及证据存放位置。源配置、账号密码、Cookie、密钥不进入正式文档；公开证据使用合成数据并检查泄漏。
5. 可重复的独立验收命令与隔离启动方式，原始私密材料留在 `.local/`，不打包进源码。
6. 资源台账：本轮创建、已回收、保留供复验的对象及原因；不清理其他任务资源。

证据索引建议使用 `docs/diagnosis-outcome-cases-evidence-index-YYYYMMDD.json`，仅含脱敏摘要、文件哈希、检查编号与路径，不含运行凭据。一个编号未执行就保留 NOT_RUN，不可用历史相似检查代替。

## 独立验收重点与本轮停点

独立验收首先重验四个容易出现表面通过的问题：新案例是否实际进入隔离执行器、人员标准是否泄漏给模型、发布并发是否冻结了正确来源版本、备份恢复后新旧历史是否完整。随后复验权限和未知命令恢复，再核对报告身份与资源台账。

开发完成后交付代码、用户文档、验收记录和独立复验入口，停在本开发包边界。20–30 例真实质量基线、Prompt/性能优化、外部 Java 目标接入另行规划；开发完成不能直接写成已通过独立验收或生产就绪。
