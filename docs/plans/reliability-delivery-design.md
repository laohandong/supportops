## 1. 交付目标与范围

本轮交付应使维护者能够确认运行的是哪个程序、定位启动依赖问题、自动重验关键页面，并从一份经过校验的备份在全新隔离环境恢复数据与检索能力。

| 纳入本轮 | 本轮不扩展 |
| --- | --- |
| 子 JVM 测试跨平台修复、Windows/Linux 实际验证 | 多 Agent、工单、技能市场、企业连接器 |
| 实际运行身份、只读环境检查、明确启动失败信息 | 集群调度、自动扩缩容、通用监控平台 |
| Chromium 自动浏览器回归、真实隔离后端和存储 | 更换前端框架、全面视觉重设计 |
| 停止应用写入后的完整备份、恢复到全新专用环境 | 在线热备、定时备份服务、原地覆盖恢复、跨版本数据库迁移 |
| CI 接入、运行手册、独立可核对的验收证据 | 模型质量基线、处理结果回填、真实服务商调用 |

实施只操作本轮建立且核对归属的隔离实例。既有工作台、模型配置、未提交文件、容器及数据卷均保留。历史恢复 Docker 或调用模型的授权不自动用于本轮环境变更。普通实现选择由开发者决定，不需要逐任务重新审批；确实涉及现有工作台停机、未知数据、协议语义冲突时说明具体阻塞。

保持 Java 21、Node 22、模块化单体和现有 GET/POST 业务接口规则。默认不新增业务表；不得修改已应用迁移。需要增加的运行元数据属于私有本地文件，不能替代业务审计。

## 3. 构建与运行身份

### 3.1 启动兼容与元数据

保留 `node scripts/start.mjs [--config=path]` 的现有默认行为、配置优先级和 JAR 副本机制。新增的运行目录、监听端口、设置文件选择应为显式选项；默认路径保持兼容，不自动覆盖旧 `.local` 配置。

每次启动生成独立 `runtimeId`，从实际复制的 JAR 计算 SHA-256。运行记录至少包含以下语义，字段名称可按现有规范确定：

| 字段 | 约束 |
| --- | --- |
| schemaVersion、runtimeId | 运行记录协议版本与唯一运行身份 |
| pid、processStartedAt | OS/JVM 的实际进程启动身份；脚本记录时间不能冒充 OS 开始时间 |
| jarSha256、applicationVersion | 来自实际运行副本；Git 提交号只是辅助，不代表脏工作区构建内容 |
| buildRevision、sourceState | 能核实时记录，无法核实时明确 unknown；含未提交工作时不得标作干净发布 |
| phase、applicationReadyAt | STARTING、READY、FAILED、STOPPED；READY 必须来自应用真实就绪信号 |
| port、exitCode、updatedAt | 实际监听端口、退出结果及观测时间；文件更新时间不证明进程存活 |

通过受控的启动参数与应用就绪回执关联 `runtimeId`、JAR、PID 和实际端口；回执使用原子替换，路径由本机启动器限定，网页不能指定。必须在注册进程后再次检查退出，覆盖进程在登记期间失败的窗口。

状态查询基于当前 OS 身份与就绪事实，不能仅依据遗留 `runtime.json` 返回正在运行。PID 重用、进程信息不可读取、回执截断、端口被其他程序占用时返回明确的未知或不匹配状态；不结束该进程、不占用其他端口来掩盖冲突。已有记录缺少新字段时只读兼容，不猜测补齐身份。

### 3.2 管理员运行信息

建议新增只读 `GET /api/ops/runtime`，通过现有认证和默认管理员规则保护：匿名 401，普通用户 403。响应使用明确 VO，给出实际运行版本、摘要、启动时间、运行身份与有限状态，不包含主机私密路径、账号、连接串、密钥或会话值。

在后台现有布局增加简短运行信息与故障指引入口，无需另建监控大屏。原 `/api/status` 的客户工作区语义保持兼容。新增业务接口继续维护中文 OpenAPI，验证生成定义。

## 4. 只读环境检查

新增 `scripts/doctor.mjs` 和 `scripts/status.mjs`，共用版本化结果模型，提供可读文本和 `--json`。建议命令语义如下：

| 命令 | 作用 |
| --- | --- |
| `node scripts/doctor.mjs --config=<path>` | 核对明确配置的启动条件与依赖；不启动工作台 |
| `node scripts/status.mjs --runtime=<runtime.json>` | 核对该实例的当前进程身份、就绪与退出状态 |
| `node scripts/start.mjs --config=<path>` | 保留原启动入口并输出本次运行记录位置与明确失败原因 |

检查项包括 JDK 21、Node、JAR 存在与摘要、端口、配置语法、MySQL 连接及只读查询、MinIO 与 ES 的有界只读请求。Docker 信息只用于已声明的 Compose 部署；使用外部依赖时 Docker 缺失不构成应用故障。每项检查具有超时，总流程不得无限等待。

检查状态为 PASS、WARN、FAIL、UNKNOWN、NOT_APPLICABLE；同时记录检查范围与原因码。未配置模型应说明相关能力不可用，不阻止登录、上传和关键词功能。检查不能调用对话、嵌入或模型目录来证明模型可用；不具备鉴权实测时必须标为未验证。界面覆盖配置以现有配置实现为权威，不能仅看 env 文件宣布模型未配置。

退出语义固定：0 表示必需检查通过；1 表示存在已确认阻塞；2 表示参数/输入无效；3 表示关键条件未知、无法确认。可选能力缺失为 WARN。`status` 的确认停止可返回 0 并显示 STOPPED，不能与 READY 混淆。

禁止 doctor 触发 Flyway、建库建桶、补索引、修改模型配置、启动消费者或重置示例。启动普通 Spring 应用再读取状态不满足“只读检查”。必要的独立诊断入口属于配置/运维基础设施，不通过业务 Controller/Service 拼接 SQL；复用只读客户端前要检查构造器是否有初始化副作用。只读错误按稳定原因码输出，不透出原始连接串或认证头。

## 5. 浏览器回归与隔离夹具

### 5.1 运行方式

采用固定版本的 Playwright 与 Chromium，提交 lockfile，只用于开发和测试。保留原 `node --test src/test/js/*.test.mjs`。测试目录建议 `src/test/e2e/`，配置与编排位于 `scripts/` 或专用测试目录；浏览器测试依赖不得进入应用生产包。

测试使用最终打包 JAR 副本、真实 HTTP、真实隔离 MySQL/MinIO/ES、一次性管理员/普通用户、本地模型协议夹具。浏览器运行串行 `workers=1`，默认不自动重试失败用例。测试可通过业务 API 准备合成数据，但关键操作必须由真实页面触发。不能把主业务 API 全部 mock 后称为端到端通过。

运行器必须先登记本次资源，再创建；对既有随机名称碰撞、非空资源或未知归属立即拒绝。应用端口优先自动分配；存储服务使用本轮明确核对的独立部署。评测中心额外子进程/数据库/桶/索引也纳入归属清单，不能将 E2E 主实例误当作评测子实例。

子进程环境使用白名单，不继承真实提供商密钥、飞书凭据或宿主 `.local/providers.yml`。从独立工作目录启动，显式固定设置文件和配置来源。协议端点仅为本次回环夹具；测试中记录实际请求。夹具固定响应只验证工程链路，报告保持对应证据类别。

### 5.2 故障注入与断言

必须区分“请求未发送”与“服务端已受理但响应未送到浏览器”。后一场景在请求已经到达真实后端并有持久化受理证据后，丢弃返回到浏览器的响应；不能直接阻止出站请求替代。

使用测试专属代理或浏览器网络控制制造丢响应、短暂读取失败、延迟响应；生产包不新增测试控制接口。断言同时检查页面状态、实际请求 method/path/body/requestId、独立数据库计数和原始业务回执。进程故障测试继续验证真实 JVM，浏览器测试不能替代该层。

终态等待采用有界条件，不依赖固定长时间 sleep。截图、网络摘要和测试结果保留在本次目录。Trace、HAR、Cookie、请求体和备份都可能含敏感内容，原始资料只留受限本地；CI 只上传经检查的白名单报告，不上传整个 `.local` 或备份包。

## 6. 备份与恢复 V1

### 6.1 支持边界和停止写入

只支持单机、专属 Compose 存储、停止应用写入后的备份，并恢复到全新隔离 Compose 部署。保留源库名、Excel schema、桶名和索引名，通过独立服务隔离，避免改写历史 ID、引用或备份 SQL 中的名字。共享存储、外部未知写入方和跨版本恢复返回明确不支持；不得静默切换成只备份部分数据。

本轮开发及演练只能用合成源数据。实际工作台的备份/停机使用由部署操作者另行指定目标；脚本不能按进程名批量停止 Java，也不能重启 Docker。新增备份工具默认先产出只读清单，实际备份/恢复命令要求指定该清单和目标身份，防止回落到默认工作台。

开始备份前确认诊断、文档/Excel 后台处理、评测及其子进程、修复执行、飞书投递均已停止或静止。仅检查全局诊断空闲不够；有未知归属的活动执行时拒绝。停止应用后再读数据库状态、资源与文件清单。使用维护锁使新启动器不能在备份期间启动同一受控部署；身份不明的遗留锁不得仅凭超时删除。该锁只保证本机受控启动，不能宣称分布式写入隔离。

历史 UNKNOWN 可以作为历史事实备份，但相关执行进程必须已确认退出。保留状态与审计；恢复不能把 UNKNOWN 清成成功，也不能为方便备份删除待核查记录。

V1 还要求评测守卫空闲、没有待补录/补录失败的尝试、没有尚待清理的隔离资源。条件不满足时应先按现有恢复流程处理，备份工具自身不改状态、不抢占守卫。已完成尝试里的旧 `workspacePath`、进程与资源清单作为历史证据保留，不重绑定为恢复机器的当前身份。新运行使用新的受控根目录，恢复后的查询/核查不得访问源工作目录、终止源进程或清理源资源。

### 6.2 备份内容

| 内容 | 必须包含和验证 |
| --- | --- |
| MySQL 业务库 | 全部业务表、Flyway 历史、账号与归属、诊断/事件/用量、评测证据/审阅、修复与场景审计 |
| Excel schema | 动态表、内容及其与业务元数据的关联；不可只备份上传原件 |
| MinIO | 全部本部署原件、对象键、必要元数据、大小和逐对象内容摘要；遇到未支持的版本化/保留策略应拒绝或明确实现完整支持 |
| Elasticsearch | 通过官方 snapshot 保存本部署精确索引集合、映射及别名；不复制节点数据目录，不接受 PARTIAL 快照 |
| 本地状态 | 实际模型设置、提供商配置、部署配置，以及数据库仍引用的评测补录/恢复材料；外置权重记录摘要与依赖状态，不假称已打包 |
| 程序身份 | 实际 JAR 或可校验的配套发布包、SHA-256、配置协议、数据库/ES/MinIO 实际版本与镜像身份 |

MySQL 使用官方逻辑备份工具，主库与 Excel 数据在同一个已停止写入的窗口采集，保留结构和数据；不备份或覆盖整台服务器系统账号。恢复时按部署模板创建必要服务账号。认证信息通过受限配置或安全输入传递，不放入命令行日志。

ES 快照仓库通过显式可选 Compose 配置准备，不能偷偷重建现有 ES。每份备份使用独立受控仓库，等待 SUCCESS 并核对索引集合，停止该仓库写入后再封存其完整内容。恢复仓库以只读方式注册，不修改仓库内部文件。索引为空时明确记录数量零，不以缺失快照冒充空索引。

只备份和恢复本部署索引及别名，不覆盖目标集群全局设置或系统安全索引。浏览器 Cookie、会话和 localStorage 不属于备份；服务端原请求与业务历史仍需完整保留，恢复实例不搬运旧登录状态。

清单包含 `schemaVersion`、`backupId`、部署身份、程序摘要、捕获起止时间、停止写入证明、资源集合、各文件/对象大小与 SHA-256、数据计数和完成状态。先写临时结果，全部校验通过后原子标记 COMPLETE；失败保留失败清单，不能留下看似成功的目录。哈希用于检测损坏，不等同于可信签名；V1 仅接受操作者指定的可信本地备份。

配置、业务数据和账号摘要属于敏感备份内容，放在私有目录并验证权限（Windows ACL 与 POSIX 权限分别处理）。可分享报告只含脱敏摘要，不能复制原始配置或凭据。文件校验和是私有清单内容，不应为低熵秘密生成公开指纹。加密远程备份和密钥管理不在本轮范围内。

### 6.3 恢复与验证

1. 校验清单版本、完成状态、全部摘要、所需工具与版本；拒绝绝对归档路径、`..`、符号链接/硬链接逃逸及异常解包规模。校验失败不得开始写目标。
2. 创建新的部署身份、端口、数据卷和工作目录。目标必须为空且与源服务/卷/目录不同；目标非空立即拒绝，不删除、不覆盖、不提供绕过保护的 force 参数。
3. 保持应用停止，先恢复主库与 Excel，再恢复 MinIO 对象和 ES 快照。校验表/对象/索引集合及关键内容摘要，不能只比较总行数。恢复中断标记 PARTIAL，不自动向未知半成品追加；保留可核查清单，以另一个新目标重做。
4. 原配置作为私密原始材料保留，另生成本次恢复配置，仅更换目标连接和目录，不改写源备份。恢复验收默认禁用飞书、评测消费者、后台文档任务与真实模型调用，防止恢复后自动向外发送或重新消费历史任务。
5. 以配套 JAR 启动恢复实例，先核对 Flyway 历史、历史问答/用量、归属、原件下载、Excel 查询、关键词检索、旧版本过滤、评测报告/审阅、修复与场景审计。向量数据使用本地协议夹具验证恢复完整性，不要求真实模型。
6. 验证启动后的合法恢复状态迁移：旧实例审批不能执行，原请求仍能查询，未知执行不重放。对允许变化的恢复字段建立明确差异清单，不能要求所有表在启动后逐字不变，也不能忽略其他差异。

恢复成功标准是上述数据与业务可用性同时满足。服务能启动或登录页面能打开不足以证明恢复成功。内置示例的内存环境按现有启动语义重建；备份不承诺保存内存回执或延续旧审批。

- Windows：执行完整 Java/JavaScript 回归和 Chromium 流程，至少运行三阶段真实 JVM 崩溃测试、启动身份检查及恢复演练。Windows 的 Linux 容器依赖在已核对的本机 Docker Desktop 环境验证；不要求 GitHub 托管 Windows job 启动 Linux Compose。
- 无远端工作流授权或运行条件时，可用独立 Linux 容器/环境验证命令本身。报告须区分本地 Linux 通过与 GitHub Actions 实际运行通过，未推送不能宣称远端 CI 已绿。
- 新增核心检查不可被 `continue-on-error`、条件跳过、重试后只保留成功结果所掩盖。既有可选 ONNX 结果继续单列，本轮不增加模型质量结论。

## 8. 技术依据

- [Playwright CI](https://playwright.dev/docs/ci)：固定依赖并安装配套浏览器；本轮按串行浏览器验证设计，控制共享资源竞争。
- [MySQL 8.4 备份方式](https://dev.mysql.com/doc/refman/8.4/en/backup-methods.html)：逻辑备份与恢复作为本轮数据导出基础。
- [Elasticsearch 快照与恢复](https://www.elastic.co/docs/deploy-manage/tools/snapshot-and-restore)：节点目录复制不是受支持的备份，停节点也不能使其成为有效替代；快照仓库、节点配置和版本兼容分别处理。

以上仅确定机制，实施时需与仓库实际版本核对。新增工具及具体类名可以调整，本文件中的数据、权限、恢复与验收语义不得静默削弱。
