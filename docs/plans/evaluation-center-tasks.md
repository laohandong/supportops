# 评测中心开发任务与验收清单

状态：待开发。范围由 [功能与技术设计](evaluation-center-design.md) 定义；任务完成条件不表示当前仓库已经具备对应能力。

## 1. 执行约定

- 本轮实现 V1，V1.1/V1.2 只列为后续计划，不自动开发。
- 按依赖实现、验证并继续；任务编号不是每步都要等待审批的停点。
- 先读根 AGENTS.md、本方案和涉及模块；复用有效上下文，不每步重读全部文档。
- 保留工作区与本地配置；不提交、推送、发布或替换当前工作台，除非另有明确授权。
- 不并发执行共享 target 的 Maven 构建；测试使用本次明确核对的独立存储、回环端口、运行目录。
- 默认先做真实存储与本地模型协议夹具；真实服务商调用和真实模型效果另按授权范围验收。
- 环境阻塞时继续可独立完成的实现和检查，交付单列未执行项，不将其记为通过。
- 仅在源码漂移导致数据语义、安全边界或核心依赖无法成立时提出具体差异及替代方案；类名、内部拆分和普通样式细节自行决定。

## 2. 依赖与规模

```text
EC-01 契约与复用边界 -> EC-02 数据层 -> EC-03 实验管理
EC-01 -> EC-04 受控执行器
EC-02 + EC-03 + EC-04 -> EC-05 调度、导入、取消与恢复
EC-02 + EC-05 -> EC-06 审阅与对比
EC-03 + EC-05 + EC-06 -> EC-07 管理界面
EC-01 至 EC-07 -> EC-08 隔离集成与故障验收 -> EC-09 文档与交付
```

| 任务 | 规模 | 产出 |
| --- | --- | --- |
| EC-01 | 中 | 固定协议、输入快照、CLI 可复用执行边界 |
| EC-02 | 中 | 增量迁移、实体、Mapper、事务和约束 |
| EC-03 | 中 | 管理 API、模型快照、预检查、幂等启动 |
| EC-04 | 大 | 三策略、重复运行、隔离资源、进度协议与取消 |
| EC-05 | 大 | 持久化调度、证据导入、未知执行处置、终态保护 |
| EC-06 | 中 | 人工审阅、指标、可比性、报告 |
| EC-07 | 中 | 完整后台页面及浏览器流程 |
| EC-08 | 大 | 真实存储、夹具、进程故障、权限验证证据 |
| EC-09 | 小 | 用户文档、OpenAPI 核对、验收记录 |

规模为相对复杂度，不承诺开发天数或模型运行时长。可跨多次上下文完成，每次将实际完成和未完成事项记录在交付说明中。实现初期可以先贯通单个来源检查案例，再扩展全部矩阵；单案例贯通不是最终交付。

## 3. 具体开发任务

### EC-01：冻结契约和现有评测复用边界

主要入口：`scripts/evaluate.mjs`、`evaluation/run.mjs`、`evaluation/report.mjs`、`evaluation/cases.json`、`src/test/js/evaluation.test.mjs`。

开发工作：

1. 定义 schemaVersion=1 的实验清单、逐例结果、公共事件、自动检查、公开报告契约；固定结构使用明确类型。
2. 提取可导入的启动/执行组函数；CLI 保留原参数和退出含义，模块被导入不能立即启动进程。
3. 为 evaluate 增加显式案例、问题、材料输入和进度回调，默认行为兼容旧 CLI。
4. 定义仅内置场景的评测集清单，冻结案例排序、问题、材料哈希、分片设置、审阅版本。
5. 固定脚本和输入副本，记录实际 JAR 内示例资料、Prompt/Skill 摘要；工作区源码哈希不能替代实际运行身份。
6. 明确旧结果到中心结果的转换，保留 SOURCE_CHECKED、EXECUTION_FINISHED 等含义，不增加任意历史文件导入入口。

同步定义服务端执行配置、白名单及私密文件权限要求；不得将网页输入扩展成脚本或连接参数。比较接口选择“实验 + 策略”，与底层“策略 × 重复序号”的执行组明确区分。

验收：原 JS 评测测试通过；新增检查模块导入无副作用、未知版本拒绝、场景白名单、输入冻结、工作区文件变化不改变已冻结执行包、资料摘要与子应用实际读取一致。

### EC-02：MySQL 增量迁移与业务模块

主要入口：`src/main/resources/db/migration/`、新 `src/main/java/io/supportops/evaluation/`、新 `src/main/resources/mapper/evaluation/`。

开发工作：

1. 核对最新迁移号，新建下一号迁移，不改写已应用脚本。
2. 实现设计第 7 节的数据集/案例、实验、组/样本、证据、审阅、尝试、事件、执行器互斥记录。
3. 用户关联使用现有 ID 和字符集/排序规则；创建人和审阅人来自服务端登录态。
4. 启动受理时预建计划样本，失败和取消后的未执行项仍有明确状态。
5. 实现旧状态/版本条件更新、事件幂等、样本与证据原子导入、审阅追加版本。
6. 分页、状态/时间索引、组/案例唯一约束齐全，避免全表读取后在 Java 分页。

验收：真实隔离 MySQL 覆盖空库初始化、V5 增量升级、旧诊断/上传/飞书数据可读；唯一约束、外键、事务回滚、并发更新和排序分页用独立 JDBC 查询核对，不只用同一 Mapper 互相证明。

### EC-03：实验管理、配置快照和预检查

主要入口：新 evaluation controller/service/DTO/VO；config 模块内部快照服务；`UserAccessFilter` 的权限回归测试。

开发工作：

1. 实现草稿创建/修改、分页列表、详情、复制，应用 optimistic version 规则。
2. 内置数据集幂等登记，内容变化产生新版本；GET 不隐式创建业务数据。
3. config 内部服务导出一致快照，公开描述和私密执行值分开，ProviderRegistry 保持路由解析权威。
4. 草稿无模型调用；预检查无推理和故障修改，返回短期 preflightId。
5. 启动核对版本、预检查、配置修订和摘要，保存固定 requestId，原子受理并返回 202。
6. 提供 requestId 查询；同键同内容返回原结果，同键不同内容冲突。未知响应时不生成新请求键。
7. 执行器禁用/依赖缺失时历史列表、审阅、比较和导出仍可使用。
8. 新接口仅 ADMIN，POST 保留自定义请求头；中文 OpenAPI 完整声明字段/限制/错误/异步含义。

验收：401/403、普通用户直接请求、缺请求头、草稿版本冲突、预检查过期、配置改变、并发同键/不同键、超限、未知策略、路径注入均有测试。公开响应、日志、错误、报告不得出现合成测试密钥。

### EC-04：受控执行器与三策略

主要入口：拆分后的 `scripts/evaluate.mjs` / runner 模块、`evaluation/run.mjs`、`IsolatedKnowledgeWorkspace`、受控启动适配器。

开发工作：

1. 服务端固定 Node/JAR/执行包/运行目录/测试连接，参数数组启动并隐藏窗口，禁止 shell 和网页命令。
2. 增加中心清单入口，严格校验版本；旧 --sources-only、--hybrid、--compare 保留。
3. 来源检查关闭对话/嵌入/ONNX；模型组显式设置 LEXICAL_RRF、HYBRID_RRF、HYBRID_ONNX，不继承模糊默认值。
4. 每个策略 × 重复序号独立工作空间，组内串行且每例新会话。
5. 子环境白名单传递，关闭飞书和评测 Worker；有效路由来自冻结快照，不再读全局实时设置。
6. 创建资源前登记 workspaceKey/名称，处理部分创建失败；只管理本 attempt 的资源。
7. 公共进度和原子结果不含密钥/Cookie/临时密码/私密绝对路径；校验输出大小。
8. 控制文件合作式取消，停止新案例，已知 runId 查询/取消，读取末尾证据，独立信号执行有限清理。
9. 模型失败和未知提交停止后续，不自动重发；自动检查违规但执行正常可继续采集。
10. 保存 PID/启动时间/进程身份/端口/JAR 哈希/清理结果；超时终止只针对确认归属的进程。

验收：本地协议夹具核对实际请求、mode、ranking，不把配置开关当作生效证明；覆盖向量失败不回退、ONNX 缺失、Token 未报告、慢调用、取消、密钥跨流块脱敏、部分资源创建、清理失败、旧 CLI 独立运行。真实 ONNX 文件测试单列，缺少时不得伪称已验证真实 ONNX。

### EC-05：持久化调度、证据导入和恢复

主要入口：EvaluationWorker、EvaluationRunner、EvaluationResultService、状态/事件 Mapper；名称可依职责调整。

开发工作：

1. 数据库单执行器准入、租约、心跳、fencing token；不能仅依赖 JVM synchronized。
2. 短事务领取和迁移，外部进程/HTTP 操作不持有长事务。
3. 验证事件归属/序号/协议、文件路径/摘要/长度；当前 attempt 按唯一键幂等导入。
4. 样本回答、检查和完整证据原子保存；同摘要重复无操作，不同摘要冲突。
5. 持久化游标进度和有界分页；前端评测轮询不替换诊断 SSE。
6. 处理启动前/运行中/清理阶段取消，残缺尾记录、无结果退出、超时、迟到成功。
7. 主进程重启只重新领取尚未开始的队列项；已开始实验核查后明确中断，不自动继续调用模型。
8. 身份未知或未确认退出的旧进程阻止第二执行器；提供受控清理与恢复说明。
9. 原错误和 cleanupError 分别保存，finally 异常不得覆盖主因；私密文件清理遵守进程退出边界。

验收：两个 Worker 竞争只有一个进入；旧 token 更新被拒绝；重启不增加模型 POST，已导入样本保留；PID 相同但开始时间不同不得终止；重复/缺失/非法事件有明确结果；子实例和报告文件清理后证据仍可从数据库读取。

### EC-06：人工审阅、指标、比较与报告

开发工作：

1. 七维判定、说明、证据关联、审阅版本，服务端填入审阅人。
2. 每样本一个当前审阅及追加历史；过期版本冲突，不做未经设计的多人评分聚合。
3. 实现设计规定的各指标，返回分子/分母和未知/不适用计数。
4. 保留未知用量、无回答失败、未暴露攻击、缺失配对和证据不完整，禁止补零或移出分母。
5. 按对比轴校验条件，每侧选择一个实验和策略并汇总全部重复，按 case_key/repeat_index 配对，列出差异和配对覆盖。
6. 不兼容记录只能探索性展示；策略对照不能同时偷偷改变模型/资料。
7. 从数据库生成 JSON/Markdown，包含报告格式、指标算法和审阅修订版本；不导出私密运行资料。
8. 原始日志/答案代码块保持原文，不把显示时间格式写回证据，不执行其中 HTML。

验收：用可手算样本核对分母、全部不适用、部分审阅、通过/失败/证据不足、Token 未报告、配对缺失；覆盖比较条件矩阵、并发审阅冲突、报告密钥排除、原文保持。不能输出未标注 Recall/MRR 或自动生成“模型准确率”。

### EC-07：管理页面与完整交互

主要入口：`index.html` / `app.js` 少量集成；新增 `evaluation.js`、`evaluation.css`；复用现有本地 Markdown 和 Chart.js。

开发工作：

1. 管理员菜单、实验列表、草稿/预检查/规模确认、详情、案例审阅、对比、导出。
2. 执行、自动检查、质量、清理独立展示；不能一个绿色“通过”混合表达。
3. 启动冻结 requestId/请求体；双击、刷新、超时恢复原受理，读失败不解锁盲提交。
4. 活动页约 2 秒增量轮询，终态停止；切换/隐藏/退出停止无用请求，错误有限退避。
5. 覆盖禁用、无数据、缺配置、缺 ONNX、运行失败、取消中、部分审阅、证据不足、不能严格比较。
6. 复用现有视觉风格；图表同时有可读表格，键盘/焦点/标签/错误提示完整，窄屏调整双栏和表格。
7. 证据直接读样本快照，隔离实例关闭后仍可正常操作。

验收：真实浏览器在隔离实例完成来源实验、刷新恢复、夹具模型实验、审阅、对比、导出；1440px 和约 390px 无遮挡；恶意 HTML 不执行；普通用户直调 API 403；原诊断/模型配置/飞书页面无相关回归。

## 4. 必须覆盖的验收矩阵

| ID | 场景 | 预期 |
| --- | --- | --- |
| A01 | 未登录/普通用户访问 | 401/403，后端独立校验 |
| A02 | 未配置执行包/开关关闭 | 应用可启动，历史查看正常，启动明确不可用 |
| A03 | 同键重试/双击并发 | 一次受理；不同内容冲突 |
| A04 | 预检查后配置/资料/JAR 变化 | 拒绝过期清单；已启动使用固定副本 |
| A05 | 六场景来源检查 | 真实存储与 HTTP/MCP，无对话/嵌入调用，质量不适用 |
| A06 | 三策略且至少两次重复（夹具） | 实际 mode/ranking 正确，组间独立，不当作真实模型质量 |
| A07 | 向量失败/ONNX 缺失 | 无静默回退，无伪造策略成功 |
| A08 | 模型任务提交响应丢失 | 无第二次 POST，未知保留，后续跳过 |
| A09 | 取消、主 signal 已 aborted | 合作式停止，独立抢救/清理，不启动新案例 |
| A10 | Java 主程序或 Node 异常退出 | 证据保留，不自动重跑，核查进程身份 |
| A11 | 租约过期/双 Worker/迟到成功 | 单执行器，旧 token 无权改终态 |
| A12 | 资源部分创建/清理失败 | 清单精确、核查重试，原错误保留 |
| A13 | 跨块密钥、非法路径、恶意 HTML | 不泄漏、不越界、不执行 |
| A14 | 导入回滚/重复导入 | 证据原子，不重复累计数量和用量 |
| A15 | 两页面并发审阅 | 一个成功，一个版本冲突，历史保留 |
| A16 | Token 未报告/证据不足/攻击未暴露 | 不补零，不算通过，分母明确 |
| A17 | 对照条件不同或重复数不一致 | 汇总全部重复并显示缺失配对/条件差异，不给错误提升结论 |
| A18 | 子实例及报告文件清理 | 证据、审阅、引用快照、导出仍可读 |
| A19 | 旧库升级与业务回归 | 旧数据/SSE/配置/归档/飞书语义保持 |
| A20 | 真实模型/ONNX 效果 | 单独授权及记录，未执行不以夹具替代 |

## 5. 后续任务：不纳入 V1 自动执行

### NEXT-01：检索标注与专项指标

- 从固定资料制作至少 12 个查询，人工标注相关来源和分级相关性，含无相关资料案例。
- 来源键用语料版本哈希 + 文档逻辑键 + 原文位置/内容摘要；不能跨随机库用 chunk UUID 对齐。
- 固定语料和分片后实现 Recall@5、MRR@5、nDCG@5；无相关资料查询单列，不能除零或混成零分。
- 检索实验直接使用固定查询，区别于 Agent 多轮改写后的轨迹。
- 手算小集合核验公式后再执行真实嵌入/ONNX；没有标注不展示指标值。

### NEXT-02：多模型档案与实验矩阵

- 评测专用配置和凭据引用，单次实验内多模型，不修改日常全局配置。
- 冻结各路由/参数/授权范围，明确模型 × 策略 × 案例 × 重复数。
- 验证换地址不串密钥、独立限流、未知请求不重发、用量缺失分模型统计。

### NEXT-03：案例沉淀与辅助审阅

- 管理员从历史诊断显式选择、脱敏、确认版本/问题/参考标准；现场重现经受控适配器。
- 辅助审阅记录裁判模型/提示词/输入/理由，机器意见与人工确认分开。
- 不自动把模型推断写成项目记忆或金标准，不自动向外部服务提交历史私有诊断。
