## 1. 执行安排

建议由一个开发对话完整负责 RD-01～RD-07，在同一工作区依次实现、验证、修复与复验；完成后由独立验收对话复核。任务编号不是等待批准的停点。此文档不表示已经创建、派发或启动了其他对话。

当前工作区包含评测中心和受控修复等大量已验收但未提交的文件。开始时记录 Git 状态、现有运行进程和资源，保留这些工作，不清理、不重置、不把旧改动归作本轮产出。不提交、推送、发布或替换当前工作台；无真实模型调用。

```text
RD-01 跨平台修复
    ↓
RD-02 启动身份与只读检查
    ↓
RD-03 隔离浏览器运行器
    ├─ RD-04 页面与故障回归
    └─ RD-05 备份恢复工具与演练
             ↓
RD-06 CI 接入与跨平台复验
             ↓
```

RD-04 与 RD-05 在契约稳定后可分开实现，但默认仍串行完成。若之后明确安排多个开发对话，必须划分文件所有权：启动脚本/公共测试运行器/CI 由一个集成负责人修改，其他对话只改分配模块；共享 `target/` 的 Maven 构建始终串行。不为并行而复制未经同步的完整脏工作区。

## 2. 任务清单

### RD-01：修复跨平台子进程并固定验证基线

主要入口：`RemediationPersistenceTest`、`EvaluationLifecycleTest`、`EvaluationPersistenceTest`、`.github/workflows/verify.yml`。

开发工作：

1. 核对当前 `java.exe` 问题是否仍存在；按 OS 选择当前 JDK 的 Java，不从 PATH 随机选择其他版本。
2. 小范围复用现有处理方式；路径有空格时使用参数数组，禁止拼接 shell 命令。保留超时、子进程输出、退出码及清理证据。
3. 保留 ACCEPTED、APPLIED、VERIFIED 三个真实退出边界，以及恢复后零重放、UNKNOWN、原回执核查的断言。
4. 记录最初 JDK/Node/构建环境、迁移文件摘要和已有测试结果；后续验证以最终构建为准。

完成条件：Windows/Linux 均实际启动并验证子 JVM；没有 OS 跳过或弱化断言。环境暂不支持 Linux 时继续其他工作，但本项不能标为完整通过。

### RD-02：运行身份、启动检查与可读状态

主要入口：`scripts/start.mjs`、`scripts/local-config.mjs`、配置/运行基础设施、新 `scripts/doctor.mjs`、`scripts/status.mjs`、最小管理员运行信息区域。

开发工作：

1. 实现设计第 3、4 节的运行记录与就绪回执，计算实际运行 JAR SHA-256，记录实际 PID/启动时间/端口，原子写文件。
2. 保留原启动入口，显式隔离工作目录、设置文件和日志位置；处理 JAR 复制失败、端口占用、启动期间退出及启动后异常退出。
3. 实现只读 doctor/status，所有依赖探针有界；已知失败、未知、可选能力缺失分别输出，不调用模型或执行迁移。
4. 运行身份未知时不宣称存活或自动结束进程；旧格式 runtime 兼容只读。新增维护锁与后续备份共用明确部署身份。
5. 实现管理员只读运行 API 与简短界面信息，保留原 `/api/status`。OpenAPI、匿名/普通用户拒绝和敏感字段过滤同步验证。
6. 输出脱敏继续覆盖跨块日志；JSON 错误也不得泄漏凭据。默认不增加自动 stop/restart、Docker 恢复或清理命令。

完成条件：D01～D06 通过；停机、就绪、身份未知均能稳定区分；doctor 在执行前后没有产生业务或迁移写入。

### RD-03：建立真实隔离浏览器运行器

主要入口：新 `src/test/e2e/`、固定版本 Playwright 配置和 lockfile、新 `scripts/test-e2e.mjs`；复用评测协议夹具与已有隔离资源机制。

开发工作：

1. 统一生成 suiteId、私有运行目录、资源所有权清单、JAR 副本、一次性账号及回环端口。先登记创建意图，碰撞或未知归属拒绝。
2. 复用已有客户端或拆出小型隔离助手；不能强制让旧评测 CLI 同时承担所有浏览器/运维任务，也不能改变旧 CLI 的参数与结果语义。
3. 打开真实页面并连接正式后端、真实存储；夹具只替代外部模型。协议夹具允许受控延迟和错误，不在生产 API 增加故障开关。
4. 子环境白名单和独立 cwd 保证不会读取宿主密钥/提供商文件；显式关闭飞书及无关消费者。评测用例所需消费者仅对本次专属资源开启。
5. 提供合成数据准备与独立数据库核对工具；关键操作由页面完成，测试后导出脱敏结果和可定位的失败信息。
6. 退出时核实 PID 开始时间/执行身份后停止自有进程，清理仅限精确登记的自有资源；主错误和清理错误分别保存。测试中断不影响其他工作台。

完成条件：空隔离环境能从最终 JAR 启动、登录、产生真实持久化记录；错误与中断后没有误清理；两次独立运行数据不相互继承；原 JS 测试入口保持可用。

### RD-04：实现关键页面与丢响应回归

主要入口：`src/test/e2e/`；必要时小范围补页面语义标签/稳定选择器和修复实际暴露的问题。

开发工作：

1. 实现 E01～E08 全部场景，覆盖真实导航、控件操作和刷新。
2. 丢响应必须先取得后端真实受理证据，再阻断向浏览器交付；每条断言核对对应数据库/实际调用记录。
3. 用两个页面制造配置/审批版本漂移，用同一浏览器先后登录不同账号验证本地 pending 隔离。
4. 复用原请求 method/path/body/requestId 进行查询与允许的幂等重试；未知时禁止产生替代写入。不得为测试“更好写”而放宽恢复语义。
5. 浏览器操作串行、有限条件等待、默认重试零次。失败截图与日志保留；修复后复验，不把首次失败从证据中删除。
6. 运行两个视口的关键状态检查：桌面和约 390px 窄屏，确保主要按钮、错误提示、审批状态可操作；不扩展为全面视觉改版。

完成条件：八类场景实际通过；结果能指向页面、HTTP、数据库或回执证据；测试文件不只是调用现有纯函数或匹配 HTML 字符串。

### RD-05：停写备份、全新目标恢复及拒绝路径

主要入口：新 `scripts/backup.mjs`、`scripts/restore.mjs` 及必要公共助手、显式可选的 ES 快照仓库 Compose 配置、隔离恢复演练运行器。

开发工作：

1. 按设计第 6 节实现预检清单、部署归属、维护锁和停止写入核对。脚本不擅自停止现有工作台。共享或未知写入环境明确拒绝。
2. MySQL 主库和 Excel 动态 schema 逻辑备份；MinIO 对象导出；ES 精确索引集合官方快照；本地私密配置与必要材料封存。不得以 MySQL 单库备份替代整套备份。
3. 新增版本化备份清单、大小/摘要、数量、完成状态与失败记录；私有材料与可分享报告严格分开。
4. 恢复前完整校验，强制全新部署/空目标，不改写源路径或源配置；归档解包防路径逃逸，版本不匹配与资源不完整均先拒绝。
5. 恢复中断保留 PARTIAL 和准确资源清单，不自动删除源、不向未知半成品追加；重新执行使用另一个新目标。
6. 恢复实例默认关闭真实外部调用与消费者。对评测历史中的旧绝对路径、进程和资源身份保留证据，禁止当作本机当前可操作对象。
7. 准备合成恢复数据，至少包含：ADMIN/USER、完成与归档诊断、事件/用量、项目记忆、两个版本文档和原件、Excel 表、评测样本/审阅、修复请求/审计及场景变更记录。
8. 进行一次完整恢复演练与 B01～B07 拒绝/故障验证；原始备份哈希不变，源数据不被恢复动作修改。

完成条件：数据集合、摘要、关联关系和实际浏览器/API 读取均吻合；关键词与本地夹具向量检索保留版本过滤；旧审批与未知执行不被重放；失败备份不能被识别为完整可恢复包。

## 3. 必测矩阵

### 环境与运行身份

| 编号 | 场景 | 必须证明 |
| --- | --- | --- |
| D01 | Windows/Linux 子 JVM 三阶段退出 | 实际运行正确 JDK；退出与恢复语义一致，零自动重放 |
| D02 | 正常启动、启动中失败、主动退出 | READY 只在真实就绪后出现；失败/退出更新正确，摘要对应实际副本 |
| D03 | PID 重用、旧记录、进程不可读、端口被其他程序占用 | 未知/不匹配明确；不误认、不误停、不静默换端口 |
| D04 | 缺 JDK/JAR、配置错误、依赖拒绝/超时 | 稳定有界错误；文本与 JSON 语义一致；没有凭据输出 |
| D05 | 无模型密钥、已有 UI 覆盖配置、Docker 不适用 | 基础能力不被可选模型条件阻塞；配置来源判断准确，不调用模型 |
| D06 | doctor 前后数据/迁移/资源对比及运行 API 权限 | 无隐式建库建桶/迁移/索引；匿名 401、USER 403、ADMIN 可读脱敏信息 |

### 浏览器端到端

| 编号 | 场景 | 必须证明 |
| --- | --- | --- |
| E01 | 首次初始化、登录、退出、普通用户权限 | 页面与服务端一致；普通用户不能读取管理信息或他人诊断 |
| E02 | 诊断 SSE 断线与刷新 | 恢复原 runId 与游标；没有新诊断受理、重复事件/用量或刷新导致的模型重跑 |
| E03 | 评测 A 预检后复制 B、刷新及迟到响应 | B 没有继承 A 的启动资格；B 必须自行预检；旧响应不覆盖当前页面 |
| E04 | 评测启动已受理但响应丢失 | 原 requestId/path/body 保留；查询恢复只有一个受理，不重复创建尝试 |
| E05 | 提案、批准、执行、结果与历史回看 | 真实配置变化及 200/accepted=true 回执；应用/验证分开显示，审计可核对 |
| E06 | 修复已受理但丢响应、刷新、临时 404 与历史非法 pending | 只查询或按原请求重试；404 不清记录；匹配的持久化拒绝才释放旧意图；一次副作用 |
| E07 | 待核查状态下 A 退出、B 登录、再回到 A | B 无法展示/重放 A 的 pending；A 的原请求保持不变，不生成替代写入 |
| E08 | 两页面配置版本冲突、审批后同名场景重置/重启 | 过期保存被拒绝；审批失效；没有应用配置或发送验证 POST 的副作用 |

### 备份、恢复和隔离

| 编号 | 场景 | 必须证明 |
| --- | --- | --- |
| B01 | 应用/后台/评测子进程仍活动或归属未知 | 备份拒绝；不自行停止未知进程；没有 COMPLETE 结果 |
| B02 | 完整备份恢复 | 主库、Excel、原件、ES 索引、配置封存与历史证据配套；页面/API/检索实际可用 |
| B03 | 备份缺文件、摘要错误、PARTIAL、快照失败或版本不支持 | 恢复在任何目标写入前拒绝；不能把不完整索引当成功 |
| B04 | 目标非空、与源相同、卷/路径复用、目录逃逸 | 拒绝覆盖与越界；源记录和对象摘要保持不变 |
| B05 | 导出/导入中断、磁盘写失败或依赖超时 | 准确失败/PARTIAL 状态；恢复不向半成品盲目追加；维护锁不误释放未知在途任务 |
| B06 | 恢复含旧审批、UNKNOWN、评测历史进程/路径 | 无旧执行重放、无源资源清理、无真实模型/飞书外发；允许恢复状态变化有单独差异证明 |
| B07 | 跨平台私密权限、日志与报告检查 | 原始秘密仅在受限备份；公开产物不含密钥/Cookie/密码；归档不能逃逸目标 |

矩阵检查行为，不要求机械地一行对应一个测试方法。新必测项必须有实际证据；环境不具备时填 NOT_RUN 并解释，不能勾选通过。

## 4. 独立验收交接

开发交付应提供：最终 JAR 摘要、精确启动入口、隔离资源归属清单、RD/D/E/B 状态表、Windows 与 Linux 的实际结果、浏览器失败与复验记录、恢复前后数据核对、未完成事项及清理状态。账号或私密路径通过受限本地记录交接，公开报告不写密码。

独立验收重点是抽查真实失败路径和最终产物：跨平台退出、已受理丢响应、账号隔离、旧审批失效、完整恢复，以及源工作台未被改变。开发自测通过不自动等于独立验收通过。
