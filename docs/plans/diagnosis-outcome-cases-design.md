# 诊断处理结果与评测案例沉淀 V1 设计

日期：2026-10-02。状态：已形成开发方案，尚未实现或验收。本文定义质量与处理结果阶段的首个开发包；执行顺序和验收编号见[开发任务与验收清单](diagnosis-outcome-cases-tasks.md)。

本轮交付一个完整流程：已结束诊断 → 人员确认处理结果 → 管理员整理案例 → 脱敏并冻结可复现场景 → 组成不可变评测集 → 在现有评测中心执行、审阅和导出。目标是让处理事实成为可追溯的回归输入，而不是依据任务完成状态推导问题已经解决。

## 阶段目标与范围

本方案承接[系统评审](system-review-20260929.md)的 SR-02、SR-03。[可靠性交付独立复验](../reliability-delivery-independent-reacceptance-20261002.md)已在其明确的本地范围内通过；本轮新增持久化与执行协议仍须重新验证升级、恢复和隔离边界。

| 本轮必须交付 | 明确边界 |
| --- | --- |
| 诊断处理结果、验证说明、证据引用、确认人及历史修订 | 按单个诊断轮次 `runId` 记录，不自动关闭整个会话，不改诊断终态 |
| 管理员案例候选、草稿编辑、来源追溯、人工脱敏确认 | 不自动收录整段对话，不自动把模型回答变成正确答案 |
| 不可变案例版本及自定义评测集组成 | 自定义问题和审阅标准；执行仍限现有六类受控 OrderBridge 场景和内置材料包 |
| 新案例实际接入来源检查与模型诊断执行链路 | 来源检查及本地模型协议夹具用于功能验收；真实模型效果独立记录 |
| 原请求恢复、权限、并发冲突、旧记录兼容、备份恢复 | 保留现有审批、隔离资源、取消、未知结果不重放和计量语义 |

后续开发包为人工质量基线和基于基线的优化。本轮不制作或运行 20–30 例真实模型基线，不调整 Prompt、检索预算、模型路由或 ONNX，不新增外部目标、任意资料上传与故障脚本。完整工单、派单、SLA、多 Agent、自动裁判和复杂 RBAC 不在范围内。

首版的案例是基于处理经验编写的**合成复现案例**。原诊断环境与复现环境可以不同，必须显式记录差异。不能映射到受控场景的记录可保存为候选，但不能发布成可执行案例。首版不声称能够回放任意真实现场。

## 业务身份与状态

### 诊断处理结果

一个 `runId` 最多一个结果主记录，主记录有多次不可变修订。首次保存采用 `expectedVersion=0`，成功后版本为 1；后续保存必须带当前版本并追加修订。没有记录显示“尚未回填”，不能默认显示“未解决”。

| 状态 | 中文名称 | 保存约束 |
| --- | --- | --- |
| `RESOLVED` | 已解决 | 处理措施、验证说明、至少一条验证证据均必填 |
| `PARTIALLY_RESOLVED` | 部分解决 | 处理措施、已验证部分、至少一条验证证据、剩余问题均必填 |
| `UNRESOLVED` | 未解决 | 已尝试措施或明确未处理的原因、仍存在的问题必填 |
| `UNCONFIRMED` | 无法确认 | 无法确认的原因及缺少的验证信息必填 |

各状态允许相互修订，但已有记录再次保存必须填写变更理由。页面按钮为“确认并保存处理结果”；保存人和服务器时间即该修订的确认身份，不另造审批人身份或多级审批流程。

只允许为终态诊断回填，包括 `COMPLETED`、`FAILED`、`CANCELLED`、`TIMED_OUT`、`INTERRUPTED`、`LIMIT_REACHED`；`QUEUED`、`RUNNING` 返回 409。失败诊断也可能由人员在系统外解决，故不能把回填条件限定为诊断成功。

归档后的终态诊断仍可在有权访问的详情中回填，归档和禁止续聊的规则保持不变。结果只描述所选轮次，不自动改写其他轮次、诊断终态、Token 或会话历史列表。

历史无所属人的诊断仅 ADMIN 可回填，不通过回填为原诊断补造所有者。公开服务方法必须要求明确登录身份，不能依赖内部调用允许空身份的读取路径绕过权限。

### 结果字段与证据

固定字段采用明确 DTO/VO：`status`、`actionsTaken`、`verificationSummary`、`remainingIssue`、`changeReason`、`evidence[]`。首版不新增通用附件系统。

| 证据类型 | 数据来源与规则 |
| --- | --- |
| `RUN_EVENT` | 当前诊断内已持久化事件 ID；服务端验证存在及归属，只保存有界摘要和原事件摘要值 |
| `REMEDIATION_VERIFICATION` | 服务端确认修复提案的 `sourceRunId` 等于当前诊断；快照保存执行、应用、验证三个状态以及回执摘要 |
| `MANUAL_OBSERVATION` | 人员填写验证动作、观察结果及观察时间；明确标记“人员陈述”，不包装成系统测量 |

客户端不能提交任意 URL、文件路径、SQL、脚本或执行参数作为证据采集指令。手工说明中的链接只作为不可信文本，不由服务器抓取。快照不能仅存一个会失效的子实例地址。

确认“已解决”表示人员作出的业务判断，不表示系统已证明因果关系。界面区分“人员陈述”和“已有系统证据”。单独的诊断前故障事件不满足已解决的验证证据要求；需要人员明确描述处理后的观察，或具有 `PASSED` 的关联业务验证回执。`UNKNOWN`、失败或仅应用成功的修复回执可以保留为补充证据，不能单独证明恢复；后续独立人工观察仍可支持新的人员判断。

普通用户不能浏览、选择或核查管理员修复记录。管理员加入结果中的修复证据只向诊断所有者展示经过白名单投影的状态和人工确认摘要；完整提案、操作标识、回执及跳转仍只对管理员可见。必须使用角色对应 VO，不能把原始对象发到浏览器后隐藏。

建议字段限制固定为：处理措施、验证说明各 4,000 字符；剩余问题 2,000；变更理由 1,000；证据最多 20 条，单条手工摘要最多 2,000。新命令原始请求体最多 256 KiB，超限先拒绝。保存前检查必要字段，规范化规则在 Java 与 JS 契约测试中保持一致。

### 案例条目与版本

案例条目具有稳定 `caseKey`，与 `scenario` 无关。`caseKey` 由服务端生成，例如 `case-<UUID>`；每个来源诊断最多一个条目，重复创建返回已有条目，不覆盖草稿。一个条目可以有一个工作草稿和多个已发布修订。

| 展示状态 | 含义与允许操作 |
| --- | --- |
| 候选草稿 | 尚无发布版本；可编辑、补充脱敏内容、刷新来源、归档 |
| 已发布 | 至少一个不可变发布版本；可选入评测集，可显式创建下一修订草稿 |
| 已发布且有草稿 | 新草稿编辑不影响任何已发布版本和实验 |
| 已归档 | 从案例选择器隐藏，禁止新草稿和新评测集引用；历史数据集及实验仍可查、可复现 |

“可执行”是草稿校验结果，单独使用 `SUPPORTED` 或 `CANDIDATE_ONLY` 及阻断原因，不能与发布状态混为一谈。恢复归档采用显式 POST，只恢复可见性，不修改版本。

无法映射的候选将复现场景留空并填写缺口说明；草稿可以不完整，但未知枚举、可执行参数和超限正文仍拒绝保存。发布时才要求全部受控场景与材料字段齐全，不能通过接受任意场景字符串来表示未完成。

新条目只能由管理员从已确认的处理结果创建。来源保存 `runId`、结果修订 ID、必要事件引用、采集时间和摘要；原始回答只在授权的来源详情查看。草稿可以预填经过规则脱敏的问题，标准必须由人员填写，不从模型结论自动生成。

来源结果被修订后，现有草稿显示“来源已有更新”。发布必须引用当时最新的结果修订；管理员执行“刷新来源”后重新核对，已填写的问题和标准保留，脱敏和发布确认失效。发布事务检查来源版本，避免在最终检查之后来源已变化仍继续发布。历史已发布案例永远保留原引用，不被后续处理结果静默覆盖。

### 案例内容与人工标准

草稿和发布版本保存下列明确字段，界面分组展示，不能只提供一个任意 JSON 编辑框：

- 名称、症状标签、适用应用及版本、脱敏问题（1–6,000 字符）。
- 来源说明、处理结果引用、复现方式 `SYNTHETIC_REPRODUCTION`、原现场与合成场景的差异说明。
- `adapterId=ORDERBRIDGE_BUILTIN_V1`、受控场景、服务端派生的预期 HTTP 状态、内置材料包身份与分片参数。
- 人工标准：`requiredFacts`、`allowedUncertainty`、`forbiddenConclusions`、`citationRequirements`，各为有界字符串列表；必要事实和引用要求不能为空。无法确认根因的案例应把“不能下确定结论”写入标准。
- 用途 `DEVELOPMENT` 或 `HOLDOUT`；同一案例的后续修订继承用途，不允许通过改用途或改名把开发案例变成保留测试案例。

四组人工标准合计序列化 UTF-8 不超过 32 KiB，逐项至多 500 字符，每组至多 20 项。案例名称最多 200 字符；标签最多 10 个、每个 40；差异说明最多 2,000。整体受请求体上限约束。数据库、Bean Validation、JSON 解析和前端提示应一致，不在数据库错误后才解释超长。

原始处理状态、模型原回答、人工标准、审阅意见和来源快照均不进入被测 Agent 的知识索引、系统提示、项目记忆或工具结果。Agent 只接收该案例冻结的问题，并通过原有工具读取隔离现场和适用材料。执行器可以在评测侧持有标准以生成报告，但不得送入推理输入。

保留测试集是实验纪律标识，不是新增角色体系。本轮记录稳定分组和来源关系，禁止直接改组；后续基线建设还须按根因与模板族拆分近重复案例，不能仅凭该标签宣称无数据泄漏。

### 脱敏与发布

1. 案例创建只抽取所选问题及必要证据摘要，不批量复制事件、环境变量、配置文件和对话上下文。
2. 自动检查可识别的凭据、Authorization、连接串及测试敏感标记；检出的高风险内容阻止发布。规则不能保证识别全部隐私，最终仍须人员审查。
3. 草稿保存后由服务端返回内容摘要、来源修订、可执行性和脱敏检查结果；查询校验不创建业务数据，不调用模型或现场接口。
4. 发布请求携带 `expectedVersion`、`draftHash`、`sourceOutcomeRevisionId`、`redactionConfirmed=true`、`criteriaConfirmed=true`，以及固定 `requestId`。服务器重新计算全部条件，确认人来自当前 ADMIN 登录态。
5. 发布短事务锁定来源版本和案例版本，追加不可变修订并更新当前指针；失配返回 409，不能静默采用新草稿。单管理员可以编辑并确认，界面如实记录身份，不宣称双人审核。

“发布”仅指内部案例库可用于评测，不对外发布，也不启动实验。所有案例与数据集 API 保持 ADMIN。审计只记录必要的脱敏字段、变更前后摘要和版本，禁止把被拒绝的原始敏感正文写入日志或错误响应。

## 受控复现与评测集

### 六类场景适配

| 场景 | 预期来源 HTTP | 额外验证边界 |
| --- | --- | --- |
| `unavailable` | 503 | 区分下游不可用与路径、凭据问题 |
| `credentials` | 401 | 健康接口可用不等于业务认证成功 |
| `migration` | 410 | 版本、生效配置、请求与迁移规则对应 |
| `stale-docs` | 410 | 旧版本资料不能作为当前依据 |
| `insufficient` | 410 | 明确来源缺失，不能把推断写成现场事实 |
| `injection` | 410 | 只有实际检索到攻击材料才能评价攻击暴露后的行为 |

HTTP 期望、工具集合、检索预算和环境写操作由服务端适配器目录派生，不由案例编辑者配置。首版材料包仍为现有三份 OrderBridge 资料及受控注入材料；案例保存实际材料摘要和导入参数。材料正文和场景实现不因案例编辑改变。资料、JAR 或脚本漂移时按现有预检查规则拒绝使用不匹配版本，不静默选最新资料。

适配器目录同时返回固定目标和适用版本；首版可执行目标为内置 OrderBridge 2.0。原现场的其他产品或版本仅作为来源描述，不能由客户端改名后冒充可执行目标。目录不可用时允许保存未完成草稿，发布须有完整匹配的适配器与材料身份。

同一场景允许多个不同案例编号和问题。每例都重新应用场景并验证预期现场；注入材料在该例结束后清理，同组后续案例不能继承前例污染。复现只在独立实例发生；案例编辑、检查、发布均不得切换日常工作台场景。

管理员须确认所选合成场景足以支持人工标准，差异说明必填。系统检查结构和场景约束，不能自动证明自然语言标准与场景完全一致。最终来源检查和人工核对均纳入交付。

### 不可变评测集

在现有 `evaluation_datasets`、`evaluation_cases` 基础上新增“从已发布案例组成评测集”。输入为名称、用途、按序排列的案例条目 ID 与发布修订 ID；一个版本最多 30 例、不得重复同一条目或混合 DEVELOPMENT/HOLDOUT，且必须采用同一受支持材料包和适配器版本。

服务端冻结问题、场景、材料摘要、人工标准、案例版本、用途、顺序及格式版本。相同 `datasetKey` 下相同内容摘要复用原版本，变更创建新版本；GET 不登记数据。已有实验永远指向原 `datasetId`，不能引用“案例最新版”。

`datasetKey` 长度 1–80，限定小写字母、数字和连字符；名称最多 200 字符。同内容登记返回原版本及原名称，不隐式更新显示元数据。摘要统一基于版本化的规范 JSON：属性排序固定、数组保留业务顺序、UTF-8 编码；文本规范化规则明确后先规范化再展示和冻结，不在重试时再次改写正文。Java 与 Node 使用相同契约样例核对摘要。

每次实验仍选 1–6 例、1–3 策略、1–5 重复，最多 90 样本。案例库可以积累更多记录，后续 20–30 例基线分批运行；本轮不扩大并发、调用量或超时上限。

数据集版本二增加案例修订身份、结构化标准、复现边界和用途。格式一数据集照常读取；新发布不会改写旧 JSON。旧内置数据集用途标为 `LEGACY_UNASSIGNED`，不能自动纳入保留测试集。

### 执行协议与报告兼容

格式一执行清单继续沿用原六案例编号白名单。新数据集使用格式二执行清单：案例身份独立于场景，适配器、场景、HTTP 期望、材料摘要仍经严格匹配；拒绝未知字段中的可执行配置、未知适配器和未知版本。不能通过删除旧编号校验直接开放任意执行参数。

数据集版本、执行清单版本、公共事件版本分别解析。公共事件字段不变时继续使用格式一；逐例结果增加信息应采用明确版本或有界兼容适配。实际冻结脚本与其清单必须匹配。Java 读取器、Node 校验器、清理与恢复路径都要支持已有格式一包，不只修改新执行的正常路径。

在 `EvaluationSnapshotService` 内冻结案例版本及实际执行输入；`EvaluationRunnerImpl` 的租约、fencing token、证据导入、取消和异常补录继续使用现有机制。新案例的样本身份、事件、七维审阅、导出均按稳定案例编号及发布版本关联，不能误套成内置同名案例。

比较仍要求同一数据集语义摘要与兼容冻结条件。问题、标准、材料、用途或场景发生变化时只能显示不兼容或探索性比较，不给出“模型提升”的结论。报告增加案例名称、修订、用途、合成复现方式及差异说明；默认不导出原诊断正文、来源账号、私密路径或管理员回执。

来源检查、协议夹具、真实模型执行和人工质量审阅保持独立。`SOURCE_CHECKED`、`EXECUTION_FINISHED`、`PROTOCOL_FIXTURE`、人员填写“已解决”均不直接进入模型质量通过分母。用量未报告保持现有未知语义，不补零；本轮不新增“解决率等于准确率”的统计图。

## 模块与数据设计

### 服务边界

新增 `io.supportops.outcome` 模块，采用 controller、service、service/impl、mapper、entity、dto、vo、constant 的现有分层。结果服务通过 `RunService` 的授权读取投影及 remediation 的受限证据服务获取事实，不跨模块访问 Mapper。

案例库仍属于 `evaluation`，新增 `EvaluationCaseLibraryService` 及数据集组成服务方法。依赖方向为 evaluation → outcome → agent，以及 outcome → remediation；agent 和 remediation 不反向依赖 outcome/evaluation，导航关联由前端处理。跨模块来源锁定通过服务方法和同一短事务完成，不把外部 HTTP 包入事务。

幂等摘要、分页等小型纯工具可复用；不为本轮建设通用工作流、命令总线或审批框架。Java 使用明确类型、中文 Javadoc、中文 Schema，保持 GET/POST 规范。

### 新增持久化

当前最高迁移为 V10；实施时核实后新增下一号迁移，预期名 `V11__diagnosis_outcomes_and_case_library.sql`。不得重写 B3、V4–V10 或清空数据。以下表名为计划契约，可在不改语义的情况下适应已有命名。

| 表 | 关键字段与约束 |
| --- | --- |
| `diagnosis_outcomes` | UUID 主键；`run_id` 唯一且引用 runs；`version`、当前修订号、创建与更新时间；访问权通过来源诊断判定，不信任客户端 owner |
| `diagnosis_outcome_revisions` | UUID；`outcome_id` 外键；修订号唯一；状态、措施、验证、剩余问题、变更理由、有界证据快照、摘要、服务端 actor 与确认时间；仅追加 |
| `diagnosis_outcome_requests` | `(actor_id, request_id)` 唯一；动作、目标、规范化请求摘要、终局 HTTP/错误码、资源与不可变修订引用；不保存原始敏感请求 |
| `evaluation_case_entries` | UUID；稳定 case_key 唯一；`source_run_id` 唯一；来源结果修订、经脱敏的来源摘要、草稿 JSON、草稿摘要、version、用途、最新发布修订、归档状态；来源外键齐全 |
| `evaluation_case_revisions` | UUID；`entry_id` 与发布修订号唯一；完整冻结 manifest、语义摘要、来源修订、发布人和时间；不覆盖，不级联删除 |
| `evaluation_case_events` | 递增事件 ID；条目、动作、前后版本/摘要、actor、理由与时间；创建、编辑、刷新来源、发布、归档及恢复均审计 |
| `evaluation_library_requests` | 案例命令与数据集组成的固定请求回执；规则与 outcome requests 一致，模块之间不共享业务表 |

已存在的 `evaluation_cases` 增加可空 `library_revision_id` 外键，用于新案例的完整追溯；旧内置行保持 null，不虚构来源。结构化标准放在类型化序列化的发布 manifest 中，现有 `review_criteria` 保留有界文本投影供旧展示使用。新字段使用增量迁移，不改旧记录含义。

主键沿用现有 UUID 字符串，时间沿用 UTC ISO 8601，字符集和外键排序规则与现表一致；摘要为小写 SHA-256。按来源、状态、创建时间和 ID 建必要索引；列表默认每页 20、最多 100，数据库分页，固定排序白名单。有限 manifest 使用 LONGTEXT 配合明确 DTO 序列化，不以任意 Map 代替业务模型。

结果主记录、修订和成功回执同事务提交；案例发布的版本校验、不可变修订、审计和回执同事务提交；数据集与其全部 case 行原子写入。使用受影响行数检查或行锁，统一加锁顺序：请求身份 → 来源结果 → 案例 → 数据集；并发同键由唯一约束兜底，不把约束异常当成功。

源修订、事件和发布版本保持不可变，发布检查只锁必要主记录。启动不扫描并重放这些命令；本轮没有新增后台处理队列。

### 幂等与未知响应

所有新增 POST 命令采用固定 `requestId`；正文包含对应 `expectedVersion`，发布还包含草稿摘要。摘要覆盖方法、动作、目标、规范化正文和版本，服务端身份参与请求命名空间。

- 同人、同键、同内容返回原终局回执和原资源/修订，不再次增加版本；相同键不同动作、目标或正文返回 409。
- 受理后的业务拒绝保留稳定回执；未认证、越权及无法识别请求键的畸形请求不产生业务记录。数据库故障不能伪装为已持久化拒绝。
- 查询先校验当前身份和资源读取权。重新登录、切换账号或降权不会继承另一人的请求回执。
- 浏览器发送前冻结方法、路径、正文和 requestId；未知响应仅查询原请求或显式重试同一命令。查询 404、401、网络失败不解锁生成新键。
- 保留版本冲突时的本地编辑内容；获取新版本不自动覆盖，也不把旧内容自动提交为新命令。
- 恢复信息按部署身份及用户隔离，受限浏览器存储只保存本次恢复所需的有界内容，退出清理；存储失败时明确提示恢复受限，不静默换键。沿用现有恢复工具和限制，禁止将来源完整证据或凭据写入通用 localStorage。

## API 契约

以下为新增接口规划。现有 `/api/evaluations/experiments`、样本审阅、比较、报告路径继续使用，不复制第二套实验 API。所有 POST 保留 `X-SupportOps-Request: 1`。

| 方法与路径 | 权限 | 作用与必要输入 |
| --- | --- | --- |
| GET `/api/runs/{runId}/outcome` | 所有者或 ADMIN | 无记录返回 200、`outcome=null`、版本 0；同时给出只用于界面的能力提示 |
| GET `/api/runs/{runId}/outcome/history` | 所有者或 ADMIN | 分页读取不可变修订；普通用户使用受限证据投影 |
| GET `/api/runs/{runId}/outcome/remediation-options` | ADMIN | 服务端仅按该来源诊断分页提供关联修复证据摘要；不枚举其他诊断，不执行核查 |
| POST `/api/runs/{runId}/outcome` | 所有者或 ADMIN | requestId、expectedVersion、处理结果及证据；成功 200 返回确认修订 |
| GET `/api/runs/{runId}/outcome/requests/{requestId}` | 当前操作者且有来源权限 | 原命令回执；未知返回 404，不能据此断言未受理 |
| GET `/api/evaluations/case-library` | ADMIN | 分页筛选草稿、发布、归档、用途、来源 runId |
| GET `/api/evaluations/case-library/capabilities` | ADMIN | 固定场景、目标、适用版本、材料包和上限；只读目录，不调用模型或现场 |
| POST `/api/evaluations/case-library` | ADMIN | requestId、sourceRunId、expectedOutcomeRevisionId；创建候选，首次 201，已有条目 200 |
| GET `/api/evaluations/case-library/{id}` | ADMIN | 草稿、版本、来源是否更新和结构检查结果；不触发现场或模型调用 |
| GET `/api/evaluations/case-library/{id}/revisions` | ADMIN | 分页读取发布版本 |
| GET `/api/evaluations/case-library/{id}/events` | ADMIN | 分页读取追加审计 |
| POST `/api/evaluations/case-library/{id}/draft` | ADMIN | requestId、expectedVersion、完整有界草稿；已发布后新草稿注明 basedOnRevisionId |
| POST `/api/evaluations/case-library/{id}/refresh-source` | ADMIN | requestId、expectedVersion、所见最新结果修订；更新草稿来源并使确认失效 |
| POST `/api/evaluations/case-library/{id}/publish` | ADMIN | 固定命令、版本、draftHash、sourceOutcomeRevisionId、两项确认；成功返回不可变版本 |
| POST `/api/evaluations/case-library/{id}/archive` 和 `/restore` | ADMIN | 固定命令、版本及理由；保留历史，恢复不创建新发布版本 |
| GET `/api/evaluations/library/requests/{requestId}` | ADMIN 且当前操作者 | 案例及数据集组成命令的原请求回执 |
| POST `/api/evaluations/datasets/from-cases` | ADMIN | 固定命令、datasetKey、名称、用途、有序案例及修订列表；登记新版本或返回相同内容版本 |

案例详情应能按发布修订返回冻结内容，数据集接口继续提供固定版本清单。分页字段、UUID 校验、响应封装沿用现有约定；额外身份、路径、环境和执行参数字段应拒绝，而非默默使用。

状态码及错误含义：未登录 401；后台或修复证据越权 403；他人 run、事件或无权来源统一 404；格式/未知枚举 400；超体积 413；版本冲突、来源更新、未终态、发布条件不足或请求键冲突 409。建议业务码包括 `OUTCOME_RUN_NOT_TERMINAL`、`OUTCOME_VERSION_CONFLICT`、`OUTCOME_EVIDENCE_INVALID`、`CASE_SOURCE_CHANGED`、`CASE_DRAFT_CHANGED`、`CASE_REPRODUCTION_UNSUPPORTED`、`CASE_REDACTION_REQUIRED`、`CASE_VERSION_CONFLICT`、`REQUEST_CONTENT_CONFLICT`。每个具体错误在 API 文档和生成的 OpenAPI 中对应说明。

## 界面与交互

诊断详情新增“处理结果”区域，显示当前状态、确认人/时间、版本和历史；终态时允许编辑。切换诊断后编辑内容、请求恢复和异步读取不能串到另一记录。普通用户只见本人记录；管理员有“整理为评测案例”入口，跳到案例库已有条目或创建流程。

评测中心增加“案例库”页签，保留原实验入口。案例编辑分为来源、脱敏问题、复现场景、人工标准和发布预览。检查结果明确展示材料版本、来源是否过期、阻断原因和原现场差异。来源不完整时仍能保存草稿，不显示可执行成功状态。

案例库支持选择已发布版本组成评测集；实验创建页面可选择该评测集和 1–6 例，清楚显示“案例版本已冻结”和计划诊断数量。发布按钮与开始评测按钮分开；从案例库跳转最多创建实验草稿，不自动预检查或启动模型。

处理结果和案例库使用独立 JS/CSS 模块，复用现有组件与视觉约定，只在 `app.js`、`evaluation.js`、`index.html` 增加必要接点。Markdown 和输入均视为不可信，禁用原始 HTML、脚本和危险链接。支持键盘操作、字段标签、错误聚焦、保存状态、窄屏及空列表；不对现有界面做整体重写。

## 交付与后续阶段

本轮完成条件是：新增案例确实在隔离环境执行并进入原评测报告；新旧数据、失败历史和恢复回执能够升级、备份、恢复；普通用户和管理员边界经真实 HTTP 与浏览器验证。仅完成表单、建表、接口或文档不构成闭环交付。

验收报告必须区分结构验证、真实存储、浏览器、来源检查、本地协议夹具、真实模型和人工质量。真实服务商调用不属于本轮默认执行项，不能借用历史凭据或过往单次授权擅自扩大实验。

后续基线包再确定案例清单、开发/保留集分配和真实服务运行范围，先用小批次核对成本与失败行为，再比较关键词与混合检索、每例至少三次。基线结果决定回答和耗时优化；本轮不承诺准确率或性能提升。
