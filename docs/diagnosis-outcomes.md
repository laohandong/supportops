# 诊断处理结果与脱敏来源导出

终态诊断可以由有权访问的人员回填处理结果，管理员再将确认记录整理为脱敏评测来源。处理结果、修复执行和模型质量各自保存，回填不会改写诊断回答、事件、Token、执行终态或归档标记。

## 回填处理结果

在诊断工作台选择一轮已经结束的诊断，填写处理措施或未处理原因、验证说明及证据，再点击“确认并保存处理结果”。COMPLETED、FAILED、CANCELLED、TIMED_OUT、INTERRUPTED、LIMIT_REACHED 均可回填；运行和排队中的诊断不能回填。归档后仍可按原权限查看与修订结果，不能因此续聊。

| 人员状态 | 含义与必需信息 |
| --- | --- |
| RESOLVED 已解决 | 人员判断问题已解决；必须有处理后的独立验证 |
| PARTIALLY_RESOLVED 部分解决 | 必须有处理后的独立验证，并说明剩余问题 |
| UNRESOLVED 未解决 | 说明未处理原因或已采取措施，以及剩余问题 |
| UNCONFIRMED 无法确认 | 在验证说明中明确缺少哪些验证信息 |

尚未回填返回 `outcome=null`、`version=0`，不等同于“未解决”。模型回答“已修复”、诊断前的故障事件、修复动作受理成功均不能自动生成 RESOLVED。上述状态表示人员陈述，不是系统对因果关系或模型质量的认证。

### 证据来源

| 类型 | 约束 |
| --- | --- |
| RUN_EVENT | 只能引用当前轮次已持久化事件；诊断前故障不能单独支持“已解决” |
| REMEDIATION_VERIFICATION | 仅管理员可关联相同 `sourceRunId` 的现有修复；读取只取得已保存回执，不执行、核查或发起业务验证请求 |
| MANUAL_OBSERVATION | 填写处理后的验证动作、观察结果和 UTC ISO 8601 时间；已有终态时间时，观察不能早于终态，也不能超过当前时间五分钟 |

“已解决”及“部分解决”必须包含完整人员观察，或同时为应用 APPLIED、独立验证 PASSED 且执行状态不为 UNKNOWN 的关联修复证据。修复验证失败或 UNKNOWN 不会被回填为成功；人员另行观察的成功和原修复失败事实可以同时保存。

处理措施最多 4000 字符，验证说明最多 4000，剩余问题最多 2000，变更理由最多 1000，证据最多 20 条。首次版本为 0；以后每次保存必须带所见版本和变更理由。服务端追加不可变修订，记录确认账号、UTC 时间、规范内容摘要与证据快照。并发冲突保留本地输入，重新读取版本后核对。

## 导出给独立评测平台

管理员在已有人工结果的终态诊断中点击“导出脱敏评测来源”，填写问题、摘要并核对预览。导出绑定当前结果修订，并发变化返回409。原请求和下载保留同一包，后续结果不会覆盖原包。

只导出有限身份、时间和已确认脱敏字段，不自动导出原答案、附件、账号或秘密。下载后由有权接收的独立评测项目手动导入。来源摘要证明包内容完整，不代表接收方信任或模型质量；后续来源变更须生成并重新确认新包。详见[协作说明](evaluation-split.md)。
