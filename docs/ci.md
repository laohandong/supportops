# 按变更范围验证

[Verify 工作流](../.github/workflows/verify.yml) 在面向 `main` 的 PR、`main` 推送及手动触发时运行。候选分支推送不再额外启动同一套检查；创建或更新 PR 后执行 PR 验证，合并后另核对主线提交的结果。

## 检查范围

| 变更内容 | 自动检查 |
| --- | --- |
| README、规则说明、文档及只供阅读的证据索引 | CI 分流与文档检查器的轻量用例、相关文档链接与锚点、变更验收 JSON 的语法；不安装应用依赖、不构建应用、不启动存储或浏览器 |
| Verify 工作流、`scripts/ci/`、`src/test/ci/` | 轻量检查；使用固定版本及校验和的 actionlint 核对工作流 |
| JavaScript 测试 | JavaScript 测试及依赖审计 |
| Java 测试 | 独立存储下的 Maven `verify` 与打包，不运行浏览器和恢复矩阵 |
| 前端静态文件、应用运维脚本、端到端或恢复测试、评测兼容脚本 | JavaScript 测试及运行、浏览器、恢复和边界验证；Java 输入未变时只打包所需 JAR，不重复 Java 测试 |
| Java 生产代码 | 独立存储下的 Maven `verify`，以及运行、浏览器、恢复和边界验证 |
| 运行资源、迁移、共享依赖、构建输入、协议或未识别路径 | 保守执行 JavaScript、Java 及运行矩阵的完整验证 |

混合变更取各项检查的并集。内置 Skill、示例知识等 Markdown 属于运行输入，不归入纯文档。路径规则的准确范围见 [分流实现](../scripts/ci/changes.mjs)，不能只凭文件扩展名判断。文档描述的代码行为、参数含义和历史证据仍需在审阅中对照对应实现；链接检查不能代替语义核对。

## 比较与汇总

PR 使用目标分支与 head 的共同祖先比较；主线 push 比较 `before` 到 `after`，覆盖一次推送的全部提交。删除与重命名两端均参与判断；未知路径和首次 push 进入完整验证，基准不可读取时直接失败。手动运行默认按当前提交相对父提交的变化判断，可勾选 `full` 显式执行完整回归。

`changes` 确定范围，`lightweight` 执行轻量核对，`javascript` 与 `java` 根据范围运行。`java` 作业同时承载按需执行的运行矩阵；仅运行矩阵需要时，打包阶段使用 `-DskipTests`，Java 生产代码、测试或构建输入变化时仍执行 `verify`。

始终执行的 `verify` 汇总要求分流和轻量检查成功，并逐项确认应执行作业成功、不适用作业跳过。失败、取消、缺失或无效范围输出都会使汇总失败。分支规则可将该汇总作为必需检查；本工作流不修改仓库保护规则。使用作业条件分流，避免仅按文档路径跳过整个工作流导致必需检查保持 pending，相关约定见 [GitHub 跳过工作流说明](https://docs.github.com/en/actions/how-tos/manage-workflow-runs/skip-workflow-runs)。

运行和恢复验证继续使用专属资源清单，只清理本轮拥有的资源；不读取本地工作台配置或业务数据，不下载可选 ONNX 权重，不调用真实模型。完整验证的范围与限制见 [可靠性运行与恢复](reliability-delivery.md)。

## 本地定向检查

CI 分流和文档检查器只使用 Node 内置模块，无需安装应用依赖：

```powershell
node --test src/test/ci/*.test.mjs
```

文档检查器检查变更文档，并追查引用变更目标的链接，因此删除文件或修改标题时也能发现未修改文档中的关联断链；只存在于本地、未纳入 Git 交付的目标不能通过。该检查不请求外部链接，不执行文档中的命令。
