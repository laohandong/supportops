# 用户系统

## 账号与角色

首次打开本机工作台时创建首个管理员，不提供通用默认密码。初始化由数据库固定记录锁串行化；只要已存在账号就拒绝再次初始化。管理员在“用户管理”中创建管理员或普通用户账号。用户名为 3–32 位 ASCII 字母、数字或下划线，统一小写保存；新建账号密码为 12–128 个字符。登录验证已有密码，兼容受控导入的历史短密码，不改变新建账号策略。

| 角色 | 菜单与接口 | 记录范围 |
| --- | --- | --- |
| ADMIN 管理员 | 客户工作区、知识文档、项目约束、示例环境、用量分析、模型配置、用户管理，以及 Swagger/OpenAPI | 可查看全部对话、事件和上传记录 |
| USER 普通用户 | 客户工作区、提交诊断、本人历史、事件与流式回答、取消本人任务、归档本人对话、退出登录 | 仅本人对话；不能使用知识管理、上传历史或后台接口 |

普通用户通过本次诊断的证据快照阅读引用片段，完整文档和原件由管理员管理。管理员可回看其他用户及历史未归属会话；继续诊断须新建自己的会话，不能混用他人上下文。用户管理当前提供创建和列表，不包含自助注册、密码找回、账号删除、角色修改或多租户管理。

## 会话与请求

侧边栏支持归档整个对话：普通用户仅能归档自己的对话，管理员可归档可见对话，归档结果对所有查看者生效。归档采用 `runs.archived_at` 逻辑标记，不删除任何诊断或事件；历史列表排除归档轮次，管理员用量统计、排行榜及问答回看仍包含全部记录。执行中的对话返回 409，结束后可归档；重复归档幂等，已归档会话不能追加诊断，返回 409 `SESSION_ARCHIVED`。当前不提供恢复归档入口。

`POST /api/runs/{id}/archive` 接受对话内任一轮诊断编号，无需请求体，成功返回 200 空响应；权限与认证头要求沿用诊断接口。

密码以独立随机盐及 PBKDF2-HMAC-SHA256（600000 次）派生后保存，登录时常量时间比较摘要；不保存明文密码，不将摘要或密码输出到接口。服务端会话仅保存用户编号，每次 HTTP 请求重新查询角色。登录轮换会话；退出销毁会话。Cookie 具有 HttpOnly 与 SameSite=Strict，闲置 8 小时失效；进程重启需重新登录。当前部署仅允许 HTTP 回环访问，不提供跨主机登录。

全部 `/api` 业务接口（首次初始化状态、首次创建管理员、登录除外）要求 Cookie 认证。后台接口默认仅管理员可访问，普通用户采用明确的客户接口白名单。所有 POST 请求必须携带 `X-SupportOps-Request: 1`；此头结合已有 Host、Origin、跨站检查与 SameSite Cookie 防止跨站表单提交。Swagger 已提供该头参数。每个本地实例每分钟最多受理 30 次登录或初始化请求，超限返回 429 和 Retry-After。

未登录返回 401 AUTHENTICATION_REQUIRED；权限不足返回 403 ADMIN_REQUIRED；写请求头缺失返回 403 REQUEST_HEADER_REQUIRED；访问不属于自己的诊断或尝试续聊他人会话返回 404 RUN_NOT_FOUND。固定只读 `/mcp` 继续使用独立本机 MCP 协议，不继承浏览器的后台管理权限；模型工具范围保持不变。

## 接口

| 方法与路径 | 用途 |
| --- | --- |
| GET /api/auth/setup | 查询是否需要初始化 |
| POST /api/auth/setup | 创建首个管理员并登录，参数 username、password |
| POST /api/auth/login | 账号密码登录，参数 username、password |
| GET /api/auth/me | 当前账号公开资料 |
| POST /api/auth/logout | 退出当前会话 |
| GET /api/users | 管理员查询账号列表 |
| POST /api/users | 管理员创建账号，参数 username、password、role |

账号响应只包含 id、username、role、createdAt；密码字段只允许写入。客户端不传用户归属，服务端在诊断或上传受理时捕获当前用户，在异步处理前落库。

## 已有数据库兼容

用户主键和外键明确使用 utf8mb4_bin，不依赖数据库默认排序规则。新库自动初始化；已有 MySQL 的结构升级与迁移历史接管、旧 H2 导入见 [数据库维护](database.md)。

旧对话和旧上传记录的 user_id 保持 NULL，界面显示“历史未归属”；不自动归给首个管理员。内部迁移、内部导入没有登录请求时也保留 NULL。新建用户与归属建立外键，禁止删除仍被记录引用的用户。上传幂等键重复时同时校验原提交用户，不能借同一个请求键重用其他用户的上传请求。

本机迁移前应保留数据库备份。MySQL DDL 不保证整文件事务回滚；若迁移失败，必须先核对已执行语句与 Flyway 失败记录，再按真实状态恢复，不能直接反复重跑或清空业务库。

批量评测在独立随机数据库创建一次性管理员，Cookie 只保留在进程内，不写入报告，不操作当前工作台账号。
