# OrderBridge 2.0 运行手册

## 适用范围

本文描述 SupportOps 自建示例应用 OrderBridge 2.0。示例应用将订单发送给本地受控的下游接口，所有业务数据均为合成数据。

## 配置规则

OrderBridge 2.0 使用 `sync.targetPath` 指定订单同步路径。未配置该键时，生效值为 `/v1/orders`。设置 `orders.path` 不会覆盖该默认值；这个旧键不再被 2.0 的同步模块读取。

下游当前支持的订单提交路径为 `/v2/orders`。运行时查询必须同时对照提供的配置与生效配置，文件中出现正确路径并不能证明同步模块使用了该路径。

## 下游响应

业务请求返回 `401 INVALID_CREDENTIAL` 表示该请求携带的凭据未被下游接受。健康检查不需要业务凭据，因此健康接口返回 200 不能排除认证问题。请由具备凭据管理权限的人员核查配置来源与有效性，不在诊断记录中粘贴凭据。

业务请求返回 `503 TEMPORARILY_UNAVAILABLE` 表示下游暂时无法服务；健康接口可能同时返回 503。应先核查下游状态和影响范围，再判断是否适合重试。

业务请求返回 `410 ROUTE_RETIRED` 表示请求访问了已停止支持的路径。确认实际请求路径后，核查当前部署版本的路径配置。

## 恢复验证

人工变更后发起新的订单同步请求，记录新的 requestId。成功标准为该请求返回 200 且响应中的 accepted 为 true；仅健康检查恢复不能证明业务同步成功。保留变更前后的请求记录。
